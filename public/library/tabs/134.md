# **🧱 Procedia Display/Control System (v1 Build Spec)**

## **1\. Core Concepts**

### **Entities**

* **Device**

  * id  
  * name (optional)  
  * online (bool)  
* **DisplaySurface (browser instance)**

  * id  
  * deviceId  
  * name (e.g. “Upper”, “Widescreen”)  
  * status: `offline | online | connected`  
  * lastActiveAt  
  * viewport (w, h)  
* **ControlSurface**

  * id  
  * deviceId  
  * type: `mobile | browser`

---

## **2\. States**

### **DisplaySurface State Machine**

offline → online → connected → online

### **Activity State**

* `active` \= input in last 10–15s  
* `idle` \= no input \~60s

---

## **3\. Detection**

### **On browser load**

* Register DisplaySurface  
* Send:  
  * deviceId  
  * viewport size  
  * timestamp

### **Track activity**

Listen:

* mousemove  
* keydown  
* click

Update:

lastActiveAt \= now

---

## **4\. Connect Flow (Mobile → Display)**

### **Step 1: Select surface**

User taps: `Connect`

---

### **Step 2: Evaluate conditions**

#### **Case A — Single instance**

→ immediately:

surface.status \= connected  
enterDisplayMode()

---

#### **Case B — Multiple instances**

→ trigger:

runShapeMatch()

---

#### **Case C — Active user detected**

IF:

now \- lastActiveAt \< threshold  
AND not landing page

→ show prompt:

"Open new display?"

Options:

* YES → `spawnNewInstance()`  
* NO → abort

---

## **5\. Shape Matching System**

### **On all candidate browsers**

Render:

* full-screen overlay  
* unique shape per instance

Example:

circle / triangle / square

---

### **On mobile**

Show:

* same shapes  
* label (e.g. “Upper Display”)

User taps shape → send:

selectedSurfaceId

---

### **Result**

bind surface → display  
enterDisplayMode()  
persist mapping

---

## **6\. Spawn New Display**

spawnNewInstance():  
  open new tab/window  
  load Procedia  
  mark as "pending display"

User:

* drags window  
* presses F11

Then: → treat as new DisplaySurface

---

## **7\. Display Mode**

When connected:

* hide normal UI  
* show display content only  
* optional minimal control bar

---

## **8\. Control Modes (Same Device)**

IF control surface \== display device:

Show options:

\- New Tab  
\- Split View  
\- Floating Panel

---

### **Split View**

* resizable panels  
* horizontal / vertical

---

### **Floating Panel**

* draggable  
* collapsible  
* always-on-top (within page)

---

## **9\. Input System (Hotkeys / Buttons)**

### **Mapping**

Each control \= fixed target surface

Example:

1 → Display A  
2 → Display B  
A → Display C

---

### **Input handling**

* keydown / hold  
* optional voice trigger

---

### **Output**

* results rendered on target display surface

---

## **10\. Visual States**

| State | Style |
| ----- | ----- |
| offline | gray |
| online | soft highlight |
| connected | strong accent |

---

## **11\. Constraints**

* No forced fullscreen  
* No forced window positioning  
* No reliable monitor detection  
* Browser \= source of truth

---

## **12\. Optional (Phase 2\)**

* Screen Enumeration API  
* Device grouping UI  
* Role system (teacher vs student)  
* Voice \+ speaker tracking

---

## **🔥 Key Principle (do not break)**

System assigns control.  
 User handles placement.
