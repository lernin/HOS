1\. Core Architecture Overview

  

The system consists of two primary tables that form a language-agnostic concept tree with language-specific word attachments.

  

1.1 Ontonyms (Universal Concepts)

  

Column Type Description

id BIGINT PRIMARY KEY Unique identifier, starting from 1

hypernym\_id BIGINT REFERENCES ontonyms(id) Parent concept; NULL for root

status VARCHAR(20) initialized, provisional, reviewed, stable, disputed

confidence FLOAT 0.0–1.0, certainty of concept correctness

created\_at TIMESTAMP When concept was first created

reviewed\_at TIMESTAMP Last time concept was reviewed

notes TEXT Optional human-readable description

  

1.2 Atomonyms (Language-Specific Words)

  

Column Type Description

id BIGINT PRIMARY KEY Unique identifier

string TEXT NOT NULL The word or phrase in its language

language VARCHAR(10) NOT NULL ISO 639-1 with optional dialect (en, ko, en-GB)

ontonym\_id BIGINT NOT NULL REFERENCES ontonyms(id) Universal concept this word represents

hypernym\_id BIGINT REFERENCES atomonyms(id) Parent word in same language

status VARCHAR(20) initialized, provisional, reviewed, stable, disputed

confidence FLOAT 0.0–1.0, certainty of this mapping

created\_at TIMESTAMP When atomonym was created

reviewed\_at TIMESTAMP Last review time

notes TEXT Usage notes, dialect information, etc.

  

1.3 Review Queue (Provisional Items)

  

Column Type Description

id BIGINT PRIMARY KEY Unique identifier

item\_type VARCHAR(10) ontonym or atomonym

item\_id BIGINT ID of the provisional item

reason TEXT Why it was flagged

proposed\_by VARCHAR(100) User or system that proposed it

created\_at TIMESTAMP When added to queue

resolved\_at TIMESTAMP NULL if unresolved

resolution TEXT approved, rejected, modified

3\. Scoponym Verification Function

  

\`\`\`sql

CREATE OR REPLACE FUNCTION scoponym\_check(

    candidate\_term TEXT,

    parent\_term TEXT

) RETURNS TEXT AS $$

DECLARE

    result TEXT;

BEGIN

    -- Returns: 'direct', 'indirect', or 'none'

    

    -- Step 1: Check if candidate is a type of parent

    IF NOT is\_type\_of(candidate\_term, parent\_term) THEN

        RETURN 'none';

    END IF;

    

    -- Step 2: Look for intermediate concepts

    IF EXISTS (

        SELECT 1 FROM find\_intermediate(candidate\_term, parent\_term)

    ) THEN

        RETURN 'indirect';

    END IF;

    

    RETURN 'direct';

END;

$$ LANGUAGE plpgsql;

\`\`\`

4\. Top-Down Ontonym Construction

  

4.1 Generate Candidate Hyponyms

  

For a given ontonym, generate candidate hyponyms using:

  

· AI knowledge of common categories

· Pattern-based generation (e.g., for ANIMAL → MAMMAL, BIRD, REPTILE)

· Existing language data (if atomonyms exist for this ontonym)

  

4.2 Verify Each Candidate

  

For each candidate C and parent ontonym P:

  

\`\`\`sql

SELECT scoponym\_check(C.term, P.term) INTO verification\_result;

\`\`\`

  

4.3 Process Based on Verification

  

Result Action

direct Create new ontonym as child of P

indirect Find the correct intermediate parent, create there

none Discard candidate

  

4.4 Create Ontonym Node

  

\`\`\`sql

INSERT INTO ontonyms (id, hypernym\_id, status, confidence, created\_at)

VALUES (next\_id (), parent\_id, 'provisional', 0.5, NOW());

  

INSERT INTO review\_queue (item\_type, item\_id, reason, created\_at)

VALUES ('ontonym', NEW.id, 'New concept from top-down generation', NOW());

\`\`\`

5\. Atomonym Creation (Language-Specific)

  

5.1 User Input

  

User provides:

  

· string: The word or phrase

· language: Language code

· hypernym\_id: Atomonym ID of parent word in same language

· (Optional) ontonym\_id: If known, otherwise to be resolved

  

5.2 Resolution Algorithm

  

\`\`\`

function create\_atomonym(string, language, hypernym\_id):

    \# Step 1: Find hypernym ontonym

    hypernym\_atomonym = SELECT \* FROM atomonyms WHERE id = hypernym\_id

    hypernym\_ontonym\_id = hypernym\_atomonym.ontonym\_id

    

    \# Step 2: Check if ontonym already exists for this concept

    existing = find\_matching\_ontonym(string, language, hypernym\_ontonym\_id)

    

    IF existing IS NOT NULL:

        ontonym\_id = existing.id

    ELSE:

        \# Step 3: Create new ontonym

        ontonym\_id = create\_ontonym(

            hypernym\_id = hypernym\_ontonym\_id,

            status = 'provisional'

        )

    

    \# Step 4: Create atomonym

    INSERT INTO atomonyms (

        id, string, language, ontonym\_id, hypernym\_id,

        status, confidence, created\_at

    ) VALUES (

        next\_id (), string, language, ontonym\_id, hypernym\_id,

        'provisional', 0.5, NOW()

    )

    

    \# Step 5: Queue for review

    INSERT INTO review\_queue (item\_type, item\_id, reason, created\_at)

    VALUES ('atomonym', NEW.id, 'New atomonym', NOW())

    

    RETURN atomonym\_id

\`\`\`

  

5.3 Find Matching Ontonym

  

\`\`\`sql

function find\_matching\_ontonym(string, language, hypernym\_ontonym\_id):

    \# Check if any atomonym in any language already links to an ontonym

    \# that has the same hypernym chain and represents the same concept

    

    \# Look for existing atomonyms with same hypernym\_ontonym\_id

    SELECT DISTINCT o.id

    FROM ontonyms o

    JOIN atomonyms a ON a.ontonym\_id = o.id

    WHERE o.hypernym\_id = hypernym\_ontonym\_id

      AND a.language \!= language  -- different language is fine

    LIMIT 1

\`\`\`

6\. Provisional Items and Review Queue

  

6.1 Status Lifecycle

  

Status Meaning Action

initialized Just created Queue for review

provisional Under review In review queue, confidence \< 0.7

reviewed Passed initial review Confidence \>= 0.7, stable enough for use

stable Well-established No further review needed unless disputed

disputed Conflicting evidence Requires human intervention

  

6.2 Confidence Thresholds

  

· 0.0–0.3: Highly uncertain, likely needs review

· 0.3–0.7: Provisional, usable but flagged

· 0.7–0.9: Reviewed, stable for most uses

· 0.9–1.0: Stable, rarely changes

  

6.3 Review Process

  

Periodic batch review of review\_queue:

  

\`\`\`sql

SELECT \* FROM review\_queue WHERE resolved\_at IS NULL

ORDER BY created\_at ASC;

\`\`\`

  

For each item:

  

· Present to reviewer (human or AI)

· Reviewer approves, rejects, or modifies

· Update item status and confidence

· Set resolved\_at and resolution

7\. Gap Detection

  

7.1 Missing Language Coverage

  

\`\`\`sql

\-- Find concepts that have Korean atomonyms but no English atomonyms

SELECT o.id, o.notes

FROM ontonyms o

WHERE EXISTS (

    SELECT 1 FROM atomonyms a

    WHERE a.ontonym\_id = o.id AND a.language = 'ko'

) AND NOT EXISTS (

    SELECT 1 FROM atomonyms a

    WHERE a.ontonym\_id = o.id AND a.language = 'en'

)

ORDER BY o.id;

\`\`\`

  

7.2 Missing Hypernym Links

  

\`\`\`sql

\-- Find atomonyms without hypernyms (should be rare)

SELECT \* FROM atomonyms

WHERE hypernym\_id IS NULL AND string \!= 'ENTITY'

AND language = 'en';

\`\`\`

  

7.3 Orphaned Ontonyms

  

\`\`\`sql

\-- Find ontonyms with no atomonyms (should be reviewed)

SELECT o.id, o.status, o.notes

FROM ontonyms o

LEFT JOIN atomonyms a ON a.ontonym\_id = o.id

WHERE a.id IS NULL

AND o.hypernym\_id IS NOT NULL;

8\. Breadth-First Construction Loop

  

\`\`\`

function build\_tree\_from\_entity(max\_depth):

    queue = \[(1, 1)\]  \# (ontonym\_id, current\_depth)

    

    while queue not empty and current\_depth \<= max\_depth:

        parent\_id, depth = queue.pop()

        

        \# Generate candidates

        candidates = generate\_hyponyms(parent\_id)

        

        for candidate in candidates:

            verification = scoponym\_check(candidate, parent\_id)

            

            if verification == 'direct':

                new\_id = create\_ontonym(candidate, parent\_id, depth+1)

                queue.append((new\_id, depth+1))

                

                \# Check for missing siblings

                missing = detect\_missing\_siblings(candidate, parent\_id)

                for m in missing:

                    create\_ontonym(m, parent\_id, depth+1, provisional=True)

            

            elif verification == 'indirect':

                \# Find correct intermediate parent

                correct\_parent = find\_correct\_parent(candidate)

                queue.append((correct\_parent, depth))

\`\`\`

13\. Build Instructions

  

Phase 1: Seed (Manual)

  

1\. Create database with schema above

2\. Insert root ENTITY (ID 1)

3\. Insert Level 2 ontonyms (PHYSICAL\_OBJECT, ABSTRACT\_ENTITY, etc.) manually

4\. Add basic English and Korean atomonyms for Level 2

  

Phase 2: Top-Down Construction

  

1\. Implement generate\_hyponyms() using AI knowledge

2\. Run breadth-first construction to Level 5

3\. Queue all new ontonyms as provisional for review

  

Phase 3: Language Expansion

  

1\. Add English and Korean atomonyms for existing ontonyms

2\. Use create\_atomonym() to link to existing ontonyms

3\. Queue new atomonyms for review

  

Phase 4: Gap Detection

  

1\. Run gap detection queries

2\. Identify missing concepts

3\. Create provisional ontonyms and atomonyms as needed

  

Phase 5: Review

  

1\. Process review queue

2\. Approve, reject, or modify provisional items

3\. Update status and confidence
