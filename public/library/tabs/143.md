# Cross Browser Continuity

# **Reframing Web Identity: A Device-Centered Model for Cross-Browser Continuity**

## **Abstract**

Modern web systems bind user identity to browser-specific sessions, resulting in fragmented user experiences across multiple browser contexts on the same physical device. This paper proposes a device-centered identity model that decouples identity from browser sessions and enables continuity across browser instances through explicit user-driven linking mechanisms. Drawing on principles from human–computer interaction (HCI), ubiquitous computing, and mental model theory, the proposed approach aligns system behavior with user expectations while preserving privacy and avoiding implicit tracking. The model introduces a structured abstraction separating human identity, device context, and browser runtime environments.

---

## **Introduction**

Web authentication systems have historically relied on browser-scoped session models, where identity is tied to cookies or local storage within a single browser instance. While effective from a technical standpoint, this model creates friction when users interact with the same system across multiple browsers on the same physical device. Users often perceive their interaction as continuous—“I am still on my computer”—yet systems treat each browser as an independent identity context.

This mismatch reflects a broader disconnect between system models and user mental models (Norman, 2013). As computing environments become more fluid, users increasingly expect seamless continuity across contexts. However, current web architectures remain constrained by browser-level isolation, limiting the ability to represent identity in a way that aligns with real-world usage.

This paper introduces a device-centered identity model that enables cross-browser continuity on a single device through explicit linking mechanisms, without relying on fingerprinting or implicit tracking.

---

## **Background and Related Work**

### **Session-Based Identity**

Traditional web systems use session tokens stored in cookies or browser storage to maintain identity. These mechanisms are inherently scoped to a single browser environment, preventing continuity across browsers even on the same device.

---

### **Ubiquitous Computing**

The concept of seamless interaction across contexts originates in ubiquitous computing, which envisions computing systems that integrate invisibly into everyday life (Weiser, 1991). In this paradigm, users should not need to manage the boundaries between devices or interfaces explicitly.

However, while ubiquitous computing addresses transitions across physical devices, it does not explicitly resolve fragmentation within a single device across multiple browser contexts.

---

### **Cross-Device Interaction**

Research in cross-device interaction explores how users interact across multiple devices simultaneously or sequentially (Hinckley et al., 2014; Marquardt et al., 2012). These systems emphasize fluidity across devices but typically assume each device is a distinct unit.

The present problem differs in that multiple isolated execution environments (browsers) exist within a single physical device, creating fragmentation that is not addressed by traditional cross-device models.

---

### **Mental Models in Interaction Design**

Norman (2013) highlights the importance of aligning system behavior with user mental models. Users conceptualize their interaction at the level of physical devices rather than software containers such as browser sessions. When systems diverge from this expectation, usability issues arise.

---

### **Privacy and Identity**

Modern browsers enforce strong isolation between contexts to preserve privacy, limiting the ability to identify devices across browser boundaries. Nissenbaum’s (2010) concept of contextual integrity emphasizes that information flow should align with user expectations and social norms.

The proposed model adheres to these principles by requiring explicit user action to link contexts rather than relying on implicit tracking.

---

## **Proposed Model**

### **Conceptual Structure**

The proposed model introduces a layered abstraction:

Human → Device → Browser Clients → Tabs

* **Human**: the user’s identity  
* **Device**: a conceptual representation of a physical device  
* **Browser Client**: a browser instance with isolated storage  
* **Tab**: an execution context within a browser

This structure separates identity from execution environment, enabling continuity across browser boundaries.

---

### **Linking Mechanism**

To propagate identity across browser contexts, the system uses a short-lived, single-use token:

1. A user initiates linking from an existing browser context  
2. The system generates a secure, time-limited token  
3. The user opens the token in a new browser  
4. The system verifies the token and associates the new browser with the same device  
5. A new browser client is registered and linked to the device

This process avoids implicit tracking and ensures that linking occurs only through user intent.

---

### **System Behavior**

Once linked:

* Multiple browsers on the same device share a unified identity  
* Each browser maintains independent storage and execution context  
* The system maintains a consistent user experience across all linked contexts

---

## **Discussion**

### **Alignment with User Mental Models**

The proposed model aligns system behavior with user expectations by treating the device—not the browser—as the primary unit of interaction. This reduces friction and eliminates redundant authentication steps.

---

### **Privacy Considerations**

Unlike fingerprinting-based approaches, the model relies entirely on explicit user action. This aligns with contextual integrity by ensuring that identity propagation occurs only when intended by the user.

---

### **Comparison to Existing Systems**

| Feature | Traditional Web | Proposed Model |
| ----- | ----- | ----- |
| Identity scope | Browser session | Device |
| Cross-browser continuity | No | Yes |
| User alignment | Low | High |
| Implicit tracking | Sometimes | No |

---

### **Limitations**

* Requires user action to establish links  
* Does not automatically detect physical devices  
* Introduces additional conceptual layer (device abstraction)

However, these limitations are intentional trade-offs to preserve privacy and clarity.

---

## **Conclusion**

This paper presents a device-centered identity model that enables cross-browser continuity on a single physical device. By introducing a structured abstraction that separates identity from browser execution contexts, the model resolves a longstanding mismatch between system design and user expectations.

The contribution is not a new authentication mechanism, but a reframing of identity representation in web systems. This reframing enables simpler, more intuitive interactions while maintaining strong privacy guarantees.
