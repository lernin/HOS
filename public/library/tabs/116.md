# Ekpronym

\# White Paper 08

\#\# The Ekpronym: Primary Representative in Cross-Language Concept Representation

\*\*Author:\*\* Ashley  
\*\*Date:\*\* April 1, 2026  
\*\*Series:\*\* Foundations of the atomonym System

\---

\#\#\# 1\. Abstract

Every language has preferred ways to express concepts. When multiple isonyms (synonyms, regional variants, register alternatives) attach to the same ontonym, one term typically dominates in everyday usage. This dominant term — the \*\*ekpronym\*\* — serves as the primary linguistic representative of a concept within a specific language or language variant.

This paper defines the ekpronym, distinguishes it from other isonym types, establishes its role in the system architecture, and specifies its behavior across three cases: direct matches, ambiguous splits, and composite concepts.

\---

\#\#\# 2\. The Problem: Choosing Which Word to Show

A concept rarely has a single name.

\*\*Example — Carbonated Beverage\*\*

| Language/Variant | Isonyms |  
|------------------|---------|  
| English (US, Northeast) | soda, pop, coke, soft drink, fizzy drink |  
| English (US, Midwest) | pop, soda, coke |  
| English (UK) | fizzy drink, soft drink, pop |  
| Korean | 탄산음료, 소다, 사이다 |

When displaying this concept to a user, the system cannot show all isonyms simultaneously. It must choose one — the \*\*primary representative\*\* — while preserving the others for inspection, disambiguation, and context.

This is the ekpronym's job.

\---

\#\#\# 3\. Definition

\*\*Ekpronym\*\* (from Greek \*ἐκλέγω\* — \*eklegō\*, "to choose, select" \+ \*ὄνυμα\* — \*onyma\*, "name")

\> The primary, most commonly used isonym for a given ontonym within a specific language and region context.

\*\*Key properties:\*\*

\- Exactly one ekpronym per (ontonym, language, region) combination  
\- Determined by frequency, naturalness, and cultural salience  
\- Used for default display, primary translation lookup, and tree rendering  
\- May be null for concepts that lack a natural expression in a language (lexical gap)

\---

\#\#\# 4\. Distinctions

| Term | Definition | Example |  
|------|------------|---------|  
| \*\*Nemonym\*\* | Raw ambiguous string | "plane" |  
| \*\*Atomonym\*\* | Disambiguated meaning instance | "plane" \+ aircraft sense |  
| \*\*Isonym\*\* | Any atomonym attached to an ontonym | plane (en), avión (es), 비행기 (ko) |  
| \*\*Ekpronym\*\* | The chosen primary isonym per language | "airplane" (en-US), "avión" (es), "비행기" (ko) |

\*\*Relationship:\*\*

\`\`\`  
Ontonym (AIRCRAFT)  
    ↓  
Isonyms: aircraft, airplane, plane, jet, avión, 비행기, 飛行機  
    ↓  
Ekpronym (en-US): airplane  
Ekpronym (en-UK): aeroplane  
Ekpronym (ko): 비행기  
\`\`\`

\#\#\# 5\. Storage Model

Ekpronym is a \*\*flag\*\* on the atomonym row, not a separate table.

\*\*Atomonym table fields:\*\*

| Field | Type | Description |  
|-------|------|-------------|  
| atomonym\_id | UUIDv7 | Primary key |  
| nemonym | TEXT | The string |  
| language | TEXT | ISO code (en, ko, es, etc.) |  
| region | TEXT | Optional (US, GB, etc.) |  
| ontonym\_id | UUIDv7 | Foreign key to ontonym |  
| hypernym\_atomonym\_id | UUIDv7 | Direct hypernym (for tree construction) |  
| \*\*is\_ekpronym\*\* | BOOLEAN | True for primary representative |  
| render\_blob | JSON | Optional: cached rendering for complex cases |

\*\*Constraint:\*\* For each (ontonym\_id, language, region), at most one atomonym has \`is\_ekpronym \= true\`.

\---

\#\#\# 6\. Behavior Patterns

The ekpronym behaves differently depending on whether the concept maps cleanly across languages.

\#\#\#\# 6.1 Direct (1:1) Mapping

\*\*Example — Pencil\*\*

| Language | Ekpronym |  
|----------|----------|  
| en-US | pencil |  
| ko | 연필 |  
| fr | crayon |

\*\*System behavior:\*\*  
\- Simple translation lookup  
\- Display ekpronym directly  
\- No ambiguity

\#\#\#\# 6.2 Split (1:Many) Mapping

\*\*Example — 조카 (Korean)\*\*

Korean has one word for both niece and nephew. English splits them.

| Ontonym | Language | Ekpronym |  
|---------|----------|----------|  
| 조카 | ko | 조카 |  
| NIECE | en | niece |  
| NEPHEW | en | nephew |

\*\*System behavior:\*\*  
\- Ekpronym for 조카 in English does not exist  
\- Return \*\*pearl (aporonym)\*\* with both options  
\- Require context to resolve

\#\#\#\# 6.3 Composite (And) Mapping

\*\*Example — Saudade (Portuguese)\*\*

Portuguese has a single word for a complex emotional state that English expresses only through sentences.

| Ontonym | Language | Ekpronym |  
|---------|----------|----------|  
| SAUDADE | pt | saudade |  
| SAUDADE | en | (no single word) |

\*\*System behavior:\*\*  
\- Ekpronym in English is null  
\- Return \*\*structured composite\*\* with:  
  \- Analysis (emotion, target, condition)  
  \- Rendered sentences as atomonym chains  
\- Decomposition stored in render\_blob

\---

\#\#\# 7\. Lexical Gaps

When a language lacks an ekpronym for a concept:

\- The system does \*\*not\*\* force a translation  
\- It returns:  
  \- The concept's decomposition (analysis)  
  \- Rendered sentences  
  \- Optionally, a borrowed term with explanation

\*\*Example — Saudade in English\*\*

\`\`\`json  
{  
  "mode": "composite",  
  "analysis": {  
    "type": "emotional\_state",  
    "emotion": \["longing", "nostalgia", "love", "absence-awareness"\],  
    "target": \["person", "place", "time", "state", "unrealized possibility"\],  
    "condition": \["absent", "lost", "distant", "never\_realized"\]  
  },  
  "renderings": {  
    "primary": \["Saudade", "is", "a", "deep", "bittersweet", "feeling", ...\],  
    "short": \["Loving", "and", "missing", "something", "that", "is", "not", "there"\]  
  }  
}  
\`\`\`

\#\#\# 8\. Region and Variant Handling

Ekpronym selection can be region-sensitive.

| Ontonym | Language | Region | Ekpronym |  
|---------|----------|--------|----------|  
| CARBONATED\_BEVERAGE | en | US-NE | soda |  
| CARBONATED\_BEVERAGE | en | US-MW | pop |  
| CARBONATED\_BEVERAGE | en | UK | fizzy drink |

\*\*Implementation:\*\*  
\- Language code with optional region: \`en-US\`, \`en-GB\`, \`en-CA\`  
\- Fallback: if region-specific ekpronym missing, use language default (\`en\`)  
\- If language default missing, concept has lexical gap

\---

\#\#\# 9\. System Flow: Translation Lookup

\*\*Given:\*\* Source language concept → Target language

1\. Identify source atomonym  
2\. Get its ontonym\_id  
3\. Query atomonyms with same ontonym\_id, target language  
4\. If \`is\_ekpronym \= true\` found → return it  
5\. If multiple found → return pearl (OR)  
6\. If none found → return composite (structured analysis \+ renderings)

\---

\#\#\# 10\. Relation to Other Axionyms

| Term | Role |  
|------|------|  
| \*\*Ontonym\*\* | Concept container |  
| \*\*Isonym\*\* | Any valid representative |  
| \*\*Ekpronym\*\* | Primary chosen representative |  
| \*\*Aporonym\*\* | Pearl container (OR ambiguity) |  
| \*\*Composite\*\* | AND-structured meaning (no single word) |

\---

\#\#\# 11\. Why This Matters

The ekpronym solves a fundamental problem in cross-language systems:

\- \*\*Dictionaries\*\* pretend 1:1 mapping exists where it doesn't  
\- \*\*Translators\*\* guess and hide uncertainty  
\- \*\*Knowledge graphs\*\* ignore lexical gaps

The ekpronym approach:

\- \*\*Preserves truth\*\* (concept identity)  
\- \*\*Handles complexity\*\* (split, composite cases)  
\- \*\*Shows gaps\*\* (no fake translations)  
\- \*\*Remains usable\*\* (primary term when it exists)

\---

\#\#\# 12\. Conclusion

The ekpronym is the primary linguistic representative of a concept within a specific language and region. It is stored as a flag on the atomonym row, with at most one per (ontonym, language, region).

When an ekpronym exists, translation is direct. When it does not, the system returns either:

\- \*\*Aporonym (OR)\*\* — for concepts that split across languages  
\- \*\*Composite (AND)\*\* — for concepts requiring structured decomposition

This model respects language differences while preserving conceptual identity — a core requirement for any serious cross-language semantic system.
