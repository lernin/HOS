# **A Type-Gated Axis Framework for Ontological Classification**

## **Executive Summary**

This paper proposes a simple but powerful framework for classifying entities:

> **First determine type membership, then evaluate essential axis alignment.**

This avoids common classification errors caused by:

* surface behavior  
* incidental properties  
* contextual roles

The framework introduces:

1. **Type Gating** (hard filter)  
2. **Axis Evaluation** (essential relevance)  
3. **Hybrid Promotion** (multi-axis identity)

---

## **1\. The Core Problem**

Traditional classification often asks:

> “Where can this thing operate?”

This leads to errors:

* A forklift operates on land → incorrectly classified as a vehicle  
* A hovercraft touches land → incorrectly classified as a land vehicle

These errors arise from:

> **Confusing incidental behavior with essential identity**

---

## **2\. Principle 1: Type Gating**

> **An entity must first qualify as a member of a type before further classification**

### **Definition**

> **Type Gate:** A binary filter that determines whether an entity belongs to a candidate category.

### **Example**

| Entity | Is it a Vehicle? | Reason |
| ----- | ----- | ----- |
| Forklift | ❌ No | Primary function is lifting, not transport |
| Bicycle | ✅ Yes | Primary function is transport |
| Drone | ✅ Yes | Primary function includes transport via locomotion |

> If the Type Gate fails → classification stops.

---

## **3\. Principle 2: Axis-Based Evaluation**

Once type membership is confirmed:

> **Evaluate the entity across a defined axis using essential relevance**

### **Example Axis: Medium of Operation**

* Land  
* Water  
* Air  
* Space

---

### **Key Question**

> **“Which values on this axis are essential to what this object is, as a member of this type?”**

---

### **Not Allowed**

* Incidental contact  
* Secondary capabilities  
* Rare or edge-case usage

---

### **Examples**

| Entity | Axis Matches | Reason |
| ----- | ----- | ----- |
| Boat | Water | Cannot function without water |
| Airplane | Air | Air is essential to operation |
| Hovercraft | Land \+ Water | Both are essential to its design |
| Spaceplane | Air \+ Space | Requires both environments |

---

## **4\. Principle 3: Multi-Axis Identity**

> **An entity may align with multiple axis values if each is essential**

This is not an error — it is **true structure**.

---

## **5\. Principle 4: Hybrid Promotion**

> **Entities with multiple essential axis alignments should be promoted to distinct types**

### **Example**

Instead of:

* “a land vehicle and a water vehicle”

Use:

* **Amphibious vehicle**

---

### **Benefits**

* Avoids duplication  
* Reflects real-world design  
* Preserves clean hierarchy

---

## **6\. Distinguishing Type vs Role vs Behavior**

A critical separation:

| Concept | Meaning |
| ----- | ----- |
| **Type** | What the thing *is* |
| **Role** | What it *does in a context* |
| **Behavior** | What it *can do* |

---

### **Example: Horse**

* Type → animal  
* Role → transport (in riding event)  
* Behavior → locomotion

> **Role does not override type**

---

## **7\. Eliminating False Positives**

This framework prevents:

### **❌ Forklift as vehicle**

Fails Type Gate

### **❌ Skates as vehicle**

Transport role too weak

### **❌ Boat as land vehicle**

Land contact is incidental

---

## **8\. One-Line Algorithm**

> **1\. Apply Type Gate → 2\. Evaluate essential axis values → 3\. Allow multi-match → 4\. Promote hybrids**

---

## **9\. Implications**

This framework:

* Improves ontology precision  
* Supports disambiguation systems (STAX/Axionyms)  
* Prevents category pollution  
* Enables clean hybrid modeling

---

## **10\. Final Insight**

> **Classification must be based on essential identity, not observed behavior**
