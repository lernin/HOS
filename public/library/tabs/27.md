# Word and seed banks  

The Seed Bank & The Word Bank: A Self-Organizing System for Meaning

  

Technical Specification

  

\---

  

Part I: Core Architecture

  

1\. Executive Summary

  

The system transforms student language into concept-grounded evidence through two complementary registries:

  

Registry Purpose Analogy

Seed Bank Static reference of 100,000 word strings + POS + rank Actuarial table / IPO valuation

Word Bank Living ledger of atomonyms (meanings) with balances Stock market / wealth accumulation

  

Every time a meaning is used in context, that atomonym receives +1 deposit. No multipliers. No formulas. Just counting. Over time, balances reflect true usage, bands emerge naturally, and the system generates rich learning evidence without manual curation.

  

\---

  

2\. The Seed Bank

  

2.1 Purpose

  

The Seed Bank is a static reference table used only at the moment an atomonym is born. It contains no meanings — only strings, part-of-speech hints, and initial rank values.

  

2.2 Schema

  

\`\`\`sql

CREATE TABLE seed\_bank (

    word\_string VARCHAR(50) PRIMARY KEY,

    lemma VARCHAR(50),

    pos\_tag VARCHAR(10),

    rank INTEGER  -- 1 = most frequent, 100,000 = least frequent

);

\`\`\`

  

2.3 Source

  

A curated 100,000-word frequency list (e.g., COCA-derived), with POS tags normalized to STAX compliance. This represents 15 years of manual curation and covers \~98% of everyday language.

  

2.4 Key Property

  

The Seed Bank never changes. It is an actuarial table — a snapshot of estimated value before any real trading begins.

  

\---

  

3\. The Word Bank

  

3.1 Purpose

  

The Word Bank is the living system. Every atomonym (meaning-bearing unit) has an account. Every time that meaning is used, the account receives a deposit.

  

3.2 Schema

  

\`\`\`sql

CREATE TABLE word\_bank (

    account\_id SERIAL PRIMARY KEY,

    word\_string VARCHAR(50) NOT NULL,  -- from seed bank or new

    concept VARCHAR(100),               -- e.g., "PERFECT", "POSSESS"

    gloss TEXT,                          -- optional description

    balance BIGINT DEFAULT 0,            -- total lifetime uses

    birth\_seed INTEGER,                   -- initial value from seed bank (or 0)

    created\_at TIMESTAMP DEFAULT NOW(),

    FOREIGN KEY (word\_string) REFERENCES seed\_bank(word\_string) ON DELETE SET NULL

);

  

CREATE INDEX idx\_word\_bank\_balance ON word\_bank(balance DESC);

CREATE INDEX idx\_word\_bank\_string ON word\_bank(word\_string);

\`\`\`

  

3.3 The Birth of an atomonym (IPO)

  

The first time a word is resolved to a specific meaning:

  

\`\`\`python

def birth\_atomonym(word\_string, concept, context):

    \# Check seed bank for initial value

    seed = seed\_bank.get(word\_string)

    initial\_balance = (100001 - seed.rank) if seed else 0

    

    \# Create new account

    account = word\_bank.create(

        word\_string=word\_string,

        concept=concept,

        balance=initial\_balance,

        birth\_seed=seed.rank if seed else 0

    )

    

    \# Record this first usage as a deposit

    account.balance += 1

    account.save()

    

    return account

\`\`\`

  

Key rule: All atomonyms born from the same word string receive the same initial balance, regardless of meaning. They start equal; usage decides their fate.

4\. Voting: The Only Math

  

4.1 The Voting Rule

  

Every time a word is processed and resolved to a specific atomonym:

  

\`\`\`sql

UPDATE word\_bank 

SET balance = balance + 1 

WHERE account\_id = \[resolved account\];

\`\`\`

  

That's it. No weights. No decay. No normalization. Just +1.

  

4.2 Sources of Votes

  

· Student artifacts

· News articles

· TV transcripts

· Books

· Any text the system processes

  

All votes count equally. The market is democratic.

5\. Bands as Lenses

  

5.1 Definition

  

Bands are not stored in the database. They are defined in the lookup algorithm as fixed-size windows into the word\_bank table sorted by balance DESC.

  

\`\`\`python

BANDS = \[

    (1, 100),     \# Band 1: rows 1-100

    (2, 500),     \# Band 2: rows 101-600

    (3, 2000),    \# Band 3: rows 601-2600

    (4, 10000),   \# Band 4: rows 2601-12600

    (5, None)     \# Band 5: everything else

\]

  

def get\_band\_range(band):

    if band == 1:

        return (0, 100)

    elif band == 2:

        return (100, 600)

    elif band == 3:

        return (600, 2600)

    elif band == 4:

        return (2600, 12600)

    else:

        return (12600, None)

\`\`\`

  

5.2 Lookup Order

  

For any word being resolved:

  

1\. Check Band 1 (top 100 by balance)

2\. If not found, check Band 2

3\. If not found, check Band 3

4\. If not found, check Band 4

5\. If not found, check Band 5

  

5.3 Key Property

  

Bands are fixed. Membership is fluid. Words move between bands automatically as their balances change. No manual reclassification ever.

Part II: Emergent Properties

  

6\. Drift

  

6.1 What Drift Means

  

Over time, atomonym balances diverge based on actual usage. Heavy users (like PERFECT "have") accumulate wealth rapidly. Rare meanings (like CAUSATIVE "have") grow slowly.

  

6.2 Rate of Emergence

  

The top bands stabilize within days or weeks for common words. The shape of language emerges quickly because usage patterns are stable.

  

6.3 Obscure Words

  

Words with very low seed ranks (90,000+) may sit at near-zero balances indefinitely. This is fine — they don't distort the system.

7\. The String Distribution Formula

  

7.1 The Insight

  

For any word string with seed value S and atomonyms A₁...Aₙ with balances B₁...Bₙ:

  

· Growth of Aᵢ = Bᵢ − S

· Total usage of the string = Σ(Bⱼ − S)

· Percentage for Aᵢ = (Bᵢ − S) / Σ(Bⱼ − S)

  

7.2 What This Reveals

  

Word atomonym Balance Growth %

duck BIRD 1,024,057 1,024,000 98.7%

duck LOWER\_HEAD 13,057 13,000 1.3%

Seed — 57 — —

  

This gives a perfect empirical pie chart of how "duck" is actually used — without any manual labeling.

  

7.3 Applications

  

· Sense frequency discovery

· Domain comparison (student writing vs. news)

· Tracking language change over time

· Curriculum sequencing (teach the 98% first)

8\. Evidence Generation

  

8.1 From Deposits to Learning

  

Every deposit is also a learning data point. When a student writes a word and it resolves to an atomonym:

  

Situation Evidence Action

Correct concept + correct form Mastery demonstrated Move forward — what's next?

Correct concept + weak form (e.g., "eated") Concept known, skill weak Practice skill, keep advancing concepts

Wrong concept Concept fuzzy Reinforce concept

Novel usage Creative attempt Encourage, then refine

12\. Lookup Algorithm (Detailed)

  

\`\`\`python

def resolve\_word(word\_string, sentence\_context):

    \# Search bands in order

    for band\_num, (start, end) in BANDS.items():

        \# Get accounts for this word in current band

        accounts = db.query("""

            SELECT \* FROM word\_bank 

            WHERE word\_string = %s 

            ORDER BY balance DESC

            OFFSET %s LIMIT %s

        """, (word\_string, start, end - start))

        

        if accounts:

            \# Use AI to select correct account based on context

            selected = ai\_disambiguate(accounts, sentence\_context)

            

            \# Record the vote

            db.execute("""

                UPDATE word\_bank 

                SET balance = balance + 1 

                WHERE account\_id = %s

            """, (selected.account\_id,))

            

            return selected

    

    \# Word not found in any band → birth new atomonym

    return birth\_atomonym(word\_string, sentence\_context)

\`\`\`

13\. Domain-Specific Distributions

JOIN artifact\_log a ON r.artifact\_id = a.artifact\_id

GROUP BY atomonym\_id;
