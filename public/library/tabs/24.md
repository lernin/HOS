# Entity Principle  

### **Entity Principle**

All entities in the system belong to one of two categories:

**Eidonym** — conceptual class  
 **Idionym** — concrete instance

An **Eidonym** represents a concept that can organize or describe other things.  
 An **Idionym** represents a specific, real instance of a concept.

Examples

Eidonym

animal

dog

poodle

  

Idionym

Fido

Lassie

Categories and types are simply **positions within the classification hierarchy**, not different kinds of objects.

For example:

animal → dog → poodle → Fido

In this chain:

  - **animal**, **dog**, and **poodle** are all **Eidonyms** (conceptual classes).  
      
  - **Fido** is an **Idionym** (a specific instance).  
      

The labels **Hypernym** and **Hyponym** simply describe the **relationship between Eidonyms** within the classification structure.

### **Taxonym Structure**

Taxonym  
  Eidonym — conceptual class  
   Hypernym — category relation (animal)  
   Hyponym — type relation (dog)  
  Idionym — instance (Fido)

### **Core Insight**

The database ultimately contains only two types of objects:

Eidonyms — conceptual classes

Idionyms — real instances

Hypernym and Hyponym are **relational roles within Eidonyms**, not separate entity types.
