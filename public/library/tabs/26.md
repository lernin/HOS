# Supernyms and Distonyms  

### **Note on Supernyms and Distonyms**

The terms **Supernym** and **Distonym** describe **relative vertical position in a hierarchy**, not specific relation types.

  - **Supernym** — a concept located above another concept in a hierarchy.
  - **Distonym** — a concept located below another concept in a hierarchy.

These terms apply regardless of the underlying relation that produces the hierarchy.

Example

animal → dog → beagle → Fido

  

From the perspective of **dog**:

animal  = supernym

beagle  = distonym

Fido    = distonym

  

### **Relation Storage Principle**

In the database, only the **forward structural relations** are stored.

Stored relations

Meronym — part relation

Hyponym — subtype relation

  

Derived relations

Holonym  — whole relation (derived from Meronym)

Hypernym — category relation (derived from Hyponym)

  

### **Conceptual Role**

**Supernym** and **Distonym** are **orientation terms**, not database relations.

They simply describe **position within a hierarchy**:

Supernym → above

Distonym → below

  

This allows the system to describe hierarchical direction without introducing additional stored relation types.
