# **White Paper**

# **Event-Centered Semantic Mapping for Knowledge Representation**

### **Author: Ashley Tait (Conceptual Framework)**

# **Abstract**

Human knowledge can be organized through a small set of fundamental semantic relations. Traditional linguistic and knowledge graph systems rely heavily on **taxonomic (type-of)** and **mereological (part-of)** relations to structure information. However, these structures alone are insufficient to explain the full richness of real-world connections between entities.

Many systems introduce a vague relation such as **“related to”** or **“associated with.”** While useful pragmatically, such relations often become unstructured catch-all categories that lack explanatory clarity.

This paper proposes that many associations can instead be explained through **event participation**, where entities interact within structured **happenings**. By modeling events and their roles—such as actors, instruments, materials, and locations—many loose associations become precise semantic relationships.

The resulting framework organizes knowledge through four primary semantic dimensions:

  - **Type relations**
  - **Part relations**
  - **Event participation**
  - **Attributes**

Together, these relations allow systematic expansion of knowledge from any concept and provide a foundation for clear ontology design.

# **1. Introduction**

Humans naturally organize knowledge by identifying how entities relate to one another. Linguistics, cognitive science, and knowledge engineering have all attempted to formalize these relationships through semantic networks and ontologies.

Two relations have historically dominated these systems:

1.  **Type hierarchy (taxonomy)**
2.  **Part hierarchy (mereology)**

These relations allow concepts to be categorized and decomposed. However, they do not fully explain many relationships encountered in everyday knowledge.

For example:

doctor — hospital

hammer — nail

teacher — classroom

  

These relationships are often labeled simply as **“associated with.”**

This white paper argues that such associations are frequently better explained through **event participation**, where entities play structured roles within happenings.

# **2. The Type Hierarchy (Taxonomy)**

## **Definition**

Type relations describe **what kind of thing something is**.

This structure forms classification trees used across many domains.

## **Relations**

  - **Hypernym** — a broader category
  - **Hyponym** — a specific instance of that category

Example:

hammer

 → tool

 → equipment

 → artifact

 → physical object

  

Here:

tool is the hypernym of hammer

hammer is the hyponym of tool

  

## **Characteristics**

Type hierarchies typically form **tree structures**.

Each concept usually appears once in the taxonomy.

These hierarchies answer the question:

What kind of thing is this?

# **3. The Part Hierarchy (Mereology)**

## **Definition**

Part relations describe **how objects are composed**.

These relations explain the internal structure of entities.

## **Relations**

  - **Holonym** — the whole object
  - **Meronym** — a component of that object

Example:

car

 → engine

 → wheel

 → seat

  

Here:

car is the holonym

wheel is a meronym

  

## **Characteristics**

Part relations form **networks rather than trees**.

Example:

wheel → car

wheel → bicycle

wheel → watch

  

A single part may belong to multiple wholes.

These relations answer the question:

What components make up this object?

# **4. Event Participation (Happenings)**

## **Definition**

Events describe **situations in which entities interact**.

An event organizes multiple types of entities into a coherent structure.

Typical event participants include:

  - actors
  - recipients
  - instruments
  - materials
  - locations
  - actions
  - results

Example event:

construction event

  

Participants:

actor: carpenter

instrument: hammer

material: nails

location: construction site

result: building

  

## **Event Roles**

In linguistics, these roles are often called **semantic roles**.

Common roles include:

  - **Agent** — the entity performing an action
  - **Patient** — the entity affected by an action
  - **Instrument** — a tool used in the action
  - **Location** — where the event occurs
  - **Material** — substances used during the event
  - **Result** — the outcome produced

# **5. Events as Explanations for Association**

Many relationships labeled as **association** can be explained through shared participation in events.

Example:

Traditional knowledge graph relation:

doctor — related\_to — hospital

  

Event-based interpretation:

medical treatment event

  

Roles:

doctor → actor

hospital → location

patient → recipient

scalpel → instrument

  

In this representation, the association is no longer vague; it is explained through structured roles.

# **6. Concept Expansion Through Three Structural Dimensions**

A concept can be expanded in three fundamental directions.

## **1. Type Expansion**

Explores categories.

Example:

hammer → tool → equipment

  

## **2. Part Expansion**

Explores structural composition.

Example:

hammer → head

hammer → handle

  

## **3. Event Expansion**

Explores interactions and contexts.

Example:

hammer → construction event

  

Which reveals:

carpenter

nails

wood

building site

  

These three expansion directions allow knowledge to grow outward from any concept.

# **7. Attributes**

## **Definition**

Attributes describe **qualities or properties** of an entity.

Examples:

apple → red

hammer → heavy

steel → strong

  

Attributes differ from relations because they describe **characteristics rather than relationships between entities**.

# **8. The Elephant Mapping Principle**

An important insight of this framework is that any concept can serve as an entry point into a much larger network of knowledge.

Starting from any concept, we can expand outward through:

type relations

part relations

event participation

attributes

  

This process gradually reveals the surrounding semantic structure.

The metaphor for this process is:

grasping one part of an elephant and reconstructing the entire animal.

# **9. The Core Ontological Framework**

The proposed semantic framework consists of four primary dimensions:

TYPE

PART

EVENT

ATTRIBUTE

  

Each dimension answers a different fundamental question:

|  |  |
| :-: | :-: |
| \*\*Dimension\*\* | \*\*Question Answered\*\* |
| Type | What kind of thing is it? |
| Part | What is it made of? |
| Event | What interactions involve it? |
| Attribute | What qualities does it have? |

Together, these dimensions provide a powerful system for organizing knowledge.

# **10. Implications for Knowledge Graph Design**

Knowledge graphs often rely heavily on generic relations such as:

related\_to

associated\_with

  

While useful for storing data quickly, these relations often hide deeper semantic structures.

By incorporating event participation into knowledge models, systems can transform vague associations into **structured semantic roles**.

Example transformation:

hammer — related\_to — nail

  

becomes

construction event

   instrument: hammer

   fastener: nail

   actor: carpenter

  

This improves clarity and supports richer reasoning.

# **Conclusion**

Human knowledge can be effectively organized through a small number of fundamental semantic relations.

The most important are:

TYPE

PART

EVENT

ATTRIBUTE

  

Type relations organize categories of entities.

Part relations describe structural composition.

Event participation explains interactions between entities.

Attributes describe the qualities of those entities.

Together, these dimensions form a powerful and coherent framework for modeling real-world knowledge.

This approach provides a foundation for more structured knowledge graphs, clearer semantic reasoning, and deeper understanding of conceptual relationships.
