# insights ontonyms  

\#\# SUMMARY OF INSIGHTS

  

\---

  

\#\#\# 1. FOUNDATION

  

\- \*\*Ontonym\*\* = universal concept container (language-agnostic ID)

\- \*\*Atomonym\*\* = disambiguated string + language + definition vector

\- \*\*Referent\*\* = the actual thing in the world (for entities)

  

\---

  

\#\#\# 2. ISONYMS

  

\- \*\*Isonyms\*\* = synonyms that exceed a threshold of conceptual overlap

\- They are \*\*equal representatives\*\* of the same ontonym

\- The ontonym is \*\*inherently fuzzy\*\* — boundaries are arbitrated by thresholds, not absolute

  

\---

  

\#\#\# 3. ADELPHONYMS

  

\- \*\*Adelphonyms\*\* = siblings under the same hypernym

\- They share a parent but are distinct concepts

\- Similarity scores measure \*\*how close the siblings are\*\*, not whether they're the same

  

\---

  

\#\#\# 4. SIMILARITY SYSTEM

  

\- \*\*Axes\*\* = the dimensions that matter for comparison (selected per comparison)

\- \*\*Weights\*\* = how much each axis counts

\- \*\*Thresholds\*\* = where you draw the line for isonym membership

\- \*\*Cosine similarity\*\* = angle between vectors in your defined space

  

\---

  

\#\#\# 5. EIDONYM FIRST

  

\- \*\*Eidonym tree\*\* (hypernym/hyponym) establishes relationship type first

\- Same node → isonym candidate

\- Same parent → adelphonyms (siblings)

\- Different branches → cousins or unrelated

\- Similarity then refines, not replaces, this structural knowledge

  

\---

  

\#\#\# 6. SAME REFERENT, DIFFERENT MEANING

  

\- Two atomonyms can point to the same referent but have different \*\*semantic envelopes\*\*

\- Example: "Eiffel Tower" (English) vs "Tour Eiffel" (French) — same tower, different cultural payload

\- Language lives at the \*\*atomonym level\*\*, not the ontonym level

  

\---

  

\#\#\# 7. MEANING OVER TIME

  

\- Objects are \*\*registered once\*\* at creation

\- \*\*Logs\*\* accumulate over time — events, descriptions, interpretations

\- Meaning is \*\*derived from logs\*\*, not versioned

\- Time is a \*\*query filter\*\*, not a versioning axis

  

\---

  

\#\#\# 8. ARCHITECTURE PRINCIPLES

  

| Layer | Contains |

|-------|----------|

| \*\*Ontonym\*\* | concept ID (fuzzy cluster) |

| \*\*Atomonym\*\* | string + language + definition vector + creation date + logs |

| \*\*Eidonym tree\*\* | hypernym/hyponym relationships |

| \*\*Logs\*\* | events that shape meaning over time |

| \*\*Definition vector\*\* | axes + weights + values (can be recomputed from logs) |

  

\---

  

\#\#\# 9. YOUR SYSTEM'S UNIQUENESS

  

\- \*\*Explicit structure\*\* — not a black box

\- \*\*Fuzzy boundaries managed\*\* — not ignored

\- \*\*Time-aware meaning\*\* — not static

\- \*\*Cross-language nuance\*\* — not flattened

\- \*\*Eidonym + similarity\*\* — structure and measurement together

  

\---

  

\#\#\# 10. CORE PHRASE

  

\> \*\*Isonyms are synonyms that exceed a threshold of conceptual overlap, making them equal representatives of the same ontonym.\*\*

  

\> \*\*The ontonym is inherently fuzzy. You govern the fuzz, you don't eliminate it.\*\*
