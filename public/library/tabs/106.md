# v20.8 tree builder

🔥 ONTOLOGY ENGINE — V20.8

1\. ANTOMOMYM FOUNDATION  
 

   
The hypernym/hyponym tree is not populated by ambiguous strings (words).  
   
It is populated by antomonyms — unique identifiers, each representing a disambiguated real kind.  
   
A single string (e.g., "plane") may map to multiple anomonyms:  
   
· plane (antomonym: ANT-001) → hypernym: aircraft · plane (antomonym: ANT-002) → hypernym: geometric surface · plane (antomonym: ANT-003) → hypernym: carpentry tool  
   
Each anomonym has:  
   
· a unique identifier · exactly one hypernym (its parent) · zero or more hyponyms (its children) · a canonical name (real-world category name) · associated attributes (color, interface, etc.)  
   
Principle: Disambiguation precedes all analysis. The tree is a hierarchy of real kinds, not words.  
    
   
1\. CORE RULE — WHAT MAKES A TYPE  
 

   
A valid TYPE must change what the thing IS, based on:  
   
· structure — physical or formal organization · composition — material or constituent parts · causal mechanism — how it produces its effects · governing constraints — the primary laws or principles that determine its behavior · persistence / failure conditions — how it endures or breaks  
   
If none of these differ between two things → they are not distinct types.  
    
   
1\. REJECTION RULES  
 

   
Reject the following as types:  
   
· descriptions (red, fast, loud) · states (broken, old, new) · roles/purposes (transportation device, writing tool) · context/location (indoor, outdoor, urban) · ownership (mine, yours, rental) · temporary conditions (wet, damaged, activated)  
   
These may become attributes, but never types.  
    
   
1\. GOVERNING CONSTRAINT PRIMACY  
 

   
Determine the single most fundamental governing constraint for the concept.  
   
Ask: "What one constraint determines the majority of the thing’s structure, composition, and behavior?"  
   
Examples:  
   
· Vehicle → medium of operation (land, water, air, space) · Food → processing / structural transformation (unprocessed, processed, prepared, preserved) · Entity → physical vs abstract existence  
   
This constraint becomes the root-level split candidate.  
    
   
1\. N-DIMENSIONAL ARRAY — DISCOVERY TOOL  
 

   
During analysis:  
   
   
1\. Identify all possible axes (governing constraints, structural dimensions)  
   
2\. For each axis, identify its possible values  
   
3\. Populate the n-dimensional array to reveal all stable, real kinds at every intersection  
 

   
The array is the source of truth for discovery. It shows which combinations of constraints yield real things in the world.  
   
Do not finalize any hierarchy until the array is complete.  
    
   
1\. HYBRID RECOGNITION  
 

   
A hybrid is a stable, real kind that occupies intersections across multiple axes.  
   
Examples:  
   
· Amphibious vehicle — intersects land \+ water operation axes · Hovercraft — a specific kind of amphibious vehicle · Keyboard instrument — intersects chordophone, aerophone, electrophone axes via interface  
   
Hybrids are not:  
   
· a failure to classify · a problem to be solved · something to force into an existing single-axis category  
   
They are legitimate real kinds discovered through array analysis.  
    
   
1\. EMERGENT KIND TEST — MEMBER-FORCED CATEGORY TEST  
 

   
A candidate category (often a hybrid) must be tested by examining its members.  
   
Ask: "Do the members of this candidate category fit cleanly into existing categories, or do they force the creation of a new category because no existing category accommodates them?"  
   
· If members fit cleanly into existing categories → candidate is an attribute/facet (selection across categories) · If members do not fit into existing categories → candidate is an emergent kind and becomes a type  
   
A category earns its place in the hierarchy when its members cannot be placed elsewhere without distortion.  
    
Test Case — Amphibious vehicle:  
   
· Members: hovercraft, amphibious car, amphibious ATV · Do they fit cleanly into Land vehicle? No — they operate on water · Do they fit cleanly into Watercraft? No — they operate on land · Existing categories cannot accommodate them without distortion · Verdict: MEMBERS DO NOT FIT → EMERGENT KIND → DIRECT TYPE under Vehicle  
   
Test Case — Keyboard instrument:  
   
· Members: piano, pipe organ, synthesizer · Does piano fit cleanly into Chordophone? Yes · Does pipe organ fit cleanly into Aerophone? Yes · Does synthesizer fit cleanly into Electrophone? Yes · Each member has a clean home in an existing category · Verdict: MEMBERS FIT CLEANLY → ATTRIBUTE (interface), NOT A TYPE under Musical Instrument  
    
   
1\. ATTRIBUTE RULE  
 

   
An attribute is a distinction that does not change:  
   
· structure · composition · causal mechanism · governing constraints · persistence / failure conditions  
   
Attributes are:  
   
· valid for querying, filtering, and faceting · not represented as type nodes in the hierarchy · applied to anomonyms after disambiguation  
   
Examples:  
   
· color (red, blue) · control interface (keyboard, touch) · location (indoor, outdoor) · material (wood, metal) — when not a structural distinction  
    
   
1\. TYPE VS. ATTRIBUTE DECISION TEST  
 

   
For each candidate kind discovered in the array:  
   
Criteria Type Attribute Changes structure/composition ✓ ✗ Changes causal mechanism ✓ ✗ Defines governing constraint ✓ ✗ Changes persistence/failure ✓ ✗ Members force new category (no clean existing home) ✓ ✗ Members fit cleanly into existing categories ✗ ✓ Is a temporary condition ✗ ✓  
   
If the candidate meets type criteria → becomes a type node. If the candidate meets attribute criteria → becomes an attribute facet.  
    
   
1\. SINGLE INHERITANCE RULE  
 

   
Every anomonym has exactly one parent.  
   
· No polyhierarchy · No multiple inheritance · No "exists in two places"  
   
Hybrids that pass the Emergent Kind Test (members do not fit existing categories) are placed under one parent — the parent determined by their primary governing constraint or the coherent intermediate category they form.  
    
   
1\. DIRECTNESS RULE  
 

   
Insert missing intermediate layers.  
   
Never skip levels.  
   
If a kind has subtypes that share a coherent intermediate category, promote that category as a direct hyponym before listing its children.  
    
   
1\. CANONICAL NAMING RULE  
 

   
Use real-world category names.  
   
Prefer:  
   
· established expert terms where appropriate · standalone nouns (aircraft, marsupial, amphibious vehicle) · simpler, widely understood terms when they capture the distinction cleanly  
   
Avoid:  
   
· repeating parent (marsupial mammal) · descriptive phrases when a name exists · invented labels · unnecessary technical terms when simpler language suffices  
    
   
1\. COMPLETENESS RULE Every true kind discovered through array analysis and validated by the Emergent Kind Test must be represented as a node. No filtering by significance. The tree aims for total coverage of real kinds in the domain.  
    
   
1\. EXHAUSTIVE TESTING LOOP  
 

   
Before finalizing any split:  
   
   
1\. Generate the candidate set using the current axis model  
   
2\. Test exhaustively: For each stable, real kind in the domain, does it fit cleanly into one candidate? If not, which kinds are unaccounted for?  
   
3\. Identify escapees: Kinds that don't fit are evidence that: · the axis set is incomplete · a hybrid category is required · the candidate split is wrong  
   
4\. Iterate: Add axes, adjust, or promote hybrids until all stable kinds are accounted for  
   
5\. Do not finalize until the candidate set accounts for all significant, stable kinds without forcing misfits  
 

   
This replaces passive convergence with active, exhaustive testing.  
    
   
1\. CONVERGENCE LOOP  
 

   
Repeat the entire sequence until the result is:  
   
· minimal — no unnecessary nodes · stable — consistent across use cases · non-overlapping — no sibling categories that overlap in meaning · reality-grounded — every node corresponds to a real kind in the world · canonically named — using appropriate, clear terminology  
   
The loop iterates through:  
   
PASS 1 — Antomonym foundation (disambiguate) PASS 2 — Core rule \+ Rejection (set criteria) PASS 3 — Governing constraint (identify root candidate) PASS 4 — N-dimensional array (discover all axes and intersections) PASS 5 — Hybrid recognition (identify hybrids) PASS 6 — Emergent Kind Test — Member-Forced Category Test (validate hybrids by examining members) PASS 7 — Type vs. Attribute Decision Test (classify each candidate) PASS 8 — Single inheritance (assign parent) PASS 9 — Directness (insert intermediate layers) PASS 10 — Canonical naming PASS 11 — Significance & sufficiency (filter) PASS 12 — Exhaustive testing loop (validate) PASS 13 — Convergence check (if not converged, repeat)  
    
FINAL CHECK  
   
Each type must be:  
   
· structurally/mechanistically distinct · not role/context-based · a real kind (represented by an anomonym) · derived from the most fundamental governing constraint(s) · validated by the Emergent Kind Test — members do NOT fit cleanly into existing categories · named using clear, appropriate terms · significant enough to list · sufficient to complete the level · accounted for in the exhaustive test — no forced fits · single parent — no polyhierarchy  
   
Attributes are documented separately for faceting.  
   
Do not display reasoning. Output conclusions only.
