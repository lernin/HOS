\#\# Predicate Types in the Eidonym Ontology

\#\#\# Overview

The Eidonym Ontology organizes all concepts under a single root (\`Eidonym\`). Concepts are connected through \*\*predicates\*\* — relationships that define how one eidonym relates to another. Predicates are grouped into branches under \`Horonym\` (definition, meaning), each representing a distinct type of relationship.

\---

\#\#\# Core Principle

Every relationship between eidonyms is stored as a \*\*triple\*\*:

| Component | Description |  
|-----------|-------------|  
| \*\*Subject\*\* | The source eidonym (UUID) |  
| \*\*Predicate\*\* | The relationship type (from the ontology) |  
| \*\*Object\*\* | The target eidonym (UUID) — optionally with a value for axionyms |

\---

\#\#\# Predicate Branches

| Branch | Predicate | Direction | Example |  
|--------|-----------|-----------|---------|  
| \*\*Morphonym\*\* | \`has\_part\` / \`part\_of\` | Whole → Part | car → engine |  
| \*\*Poionym\*\* | \`has\_quality\` | Entity → Axionym | car → luxury (value) |  
| \*\*Thematonym\*\* | \`has\_member\` / \`member\_of\` | Set → Member | {cars} → sedan |  
| \*\*Katalexonym\*\* | \`has\_possession\` / \`possessed\_by\` | Possessor → Possession | owner → car |  
| \*\*Lambanonym\*\* | \`has\_content\` / \`contained\_in\` | Container → Content | tank → fuel |  
| \*\*Perionym\*\* | \`has\_context\` | Entity → Situation | doctor → hospital |  
| \*\*Skeuonym\*\* | \`has\_prerequisite\` | Action → Primer | multiplication → addition |  
| \*\*Anaptonym\*\* | \`has\_stage\` | Entity → Stage | tree → sapling |  
| \*\*Chrononym\*\* | \`has\_temporal\` | Concept → Version | smartphone → current |

\---

\#\#\# Detailed Branch Specifications

\#\#\#\# 1\. Morphonym — Construction (Part/Whole)

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_part\` | Whole → Part | The subject has the object as a component |  
| \`part\_of\` | Part → Whole | The subject is a component of the object |

\*\*Example:\*\* \`car → has\_part → engine\`    
\*\*Use:\*\* Physical composition, structural hierarchy.

\---

\#\#\#\# 2\. Poionym — Qualities (Attributes)

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_quality\` | Entity → Axionym | The subject has the object as a quality value |

\*\*Example:\*\* \`(my car) → has\_quality → (luxury)\` where \`luxury.axonym \= luxury\_scale\`    
\*\*Use:\*\* Attributes, properties, measurements, comparisons.

\---

\#\#\#\# 3\. Thematonym — Membership (Set/Member)

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_member\` | Set → Member | The subject contains the object as a member |  
| \`member\_of\` | Member → Set | The subject belongs to the object as a set |

\*\*Example:\*\* \`{sedans} → has\_member → (Toyota Camry)\`    
\*\*Use:\*\* Classification, categories, groups.

\---

\#\#\#\# 4\. Katalexonym — Possession

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_possession\` | Possessor → Possession | The subject possesses the object |  
| \`possessed\_by\` | Possession → Possessor | The subject is possessed by the object |

\*\*Example:\*\* \`(Ashley) → has\_possession → (car)\`    
\*\*Use:\*\* Ownership, legal possession, control.

\---

\#\#\#\# 5\. Lambanonym — Registration (Content)

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_content\` | Container → Content | The subject contains the object |  
| \`contained\_in\` | Content → Container | The subject is contained in the object |

\*\*Example:\*\* \`(fuel tank) → has\_content → (gasoline)\`    
\*\*Use:\*\* Physical containment, information storage.

\---

\#\#\#\# 6\. Perionym — Context (Situation)

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_context\` | Entity → Situation | The subject exists in the object context |

\*\*Example:\*\* \`(doctor) → has\_context → (hospital)\`    
\*\*Use:\*\* Environment, setting, co-occurrence.

\---

\#\#\#\# 7\. Skeuonym — Preparation (Prerequisite)

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_prerequisite\` | Action → Primer | The subject requires the object as preparation |  
| \`prerequisite\_for\` | Primer → Action | The subject prepares for the object |

\*\*Example:\*\* \`(multiplication) → has\_prerequisite → (addition)\`    
\*\*Use:\*\* Learning sequences, causal chains, dependencies.

\---

\#\#\#\# 8\. Anaptonym — Development (Stages)

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_stage\` | Entity → Stage | The subject has the object as a developmental stage |  
| \`stage\_of\` | Stage → Entity | The subject is a stage of the object |

\*\*Example:\*\* \`(tree) → has\_stage → (sapling)\`    
\*\*Use:\*\* Lifecycles, growth, maturation, decline.

\---

\#\#\#\# 9\. Chrononym — Temporal (Versions)

| Predicate | Direction | Definition |  
|-----------|-----------|------------|  
| \`has\_previous\` | Current → Previous | The subject has a previous form |  
| \`has\_current\` | Previous → Current | The subject has a current form |

\*\*Example:\*\* \`(smartphone) → has\_previous → (rotary phone)\`    
\*\*Use:\*\* Historical progression, model evolution, obsolescence.

\---

\#\#\# Triple Store Structure

All relationships are stored in a single table:

| Field | Type | Description |  
|-------|------|-------------|  
| \`subject\_uuid\` | UUIDv7 | The source eidonym |  
| \`predicate\` | string | Relationship type (e.g., \`has\_part\`, \`has\_quality\`) |  
| \`object\_uuid\` | UUIDv7 | The target eidonym |  
| \`value\` | string | Optional — for axionyms, the specific value (e.g., "luxury") |

\---

\#\#\# Benefits

| Benefit | Description |  
|---------|-------------|  
| \*\*Uniform\*\* | All relationships use the same triple structure |  
| \*\*Extensible\*\* | New predicate types can be added under existing branches |  
| \*\*Queryable\*\* | Simple to query: "find all cars with luxury \= premium" |  
| \*\*Language-agnostic\*\* | UUIDs link concepts; labels are separate |  
| \*\*Graph-ready\*\* | Triples can be loaded into any graph database |

\---

\#\#\# Future Considerations

| Area | Description |  
|------|-------------|  
| \*\*Inference\*\* | Add rules: if A \`has\_part\` B and B \`has\_part\` C, then A \`has\_part\` C |  
| \*\*Temporal predicates\*\* | Add time stamps to triples for historical tracking |  
| \*\*Confidence\*\* | Add confidence scores for probabilistic relationships |  
| \*\*Negation\*\* | Add \`not\_has\_part\` for explicit exclusions |

\---

This white paper defines the predicate layer of the Eidonym Ontology, providing a foundation for all relationships between concepts.
