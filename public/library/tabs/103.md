\#\# Abstract

This white paper presents a complete framework for representing meaning across languages, regions, and cultures. The system separates \*\*concept identity\*\* from \*\*linguistic expression\*\* using three core constructs: \*\*ontonyms\*\* (universal concept containers), \*\*atomonyms\*\* (language‑bound strings), and \*\*isonyms\*\* (honored representatives of an ontonym). The eidonym tree (hypernym‑hyponym hierarchy) is composed entirely of ontonyms, with isonym clusters attached as leaves. A structural similarity metric based on the \*\*hodonym\*\* (path between nodes) measures relatedness using a small set of tunable levers. Special cases (abstract/concrete, tautonyms, same‑line relationships) are handled with simple rules. The framework addresses classic problems in knowledge graphs and ontologies — polyhierarchy, synonyms, cross‑language alignment, lexical gaps, disambiguation, and scalability — without requiring black‑box embeddings or arbitrary target categories.

\---

\#\# 1\. Introduction

Natural language is ambiguous. A word like "plane" maps to multiple concepts (aircraft, geometric surface, carpentry tool). A concept like "seating furniture" maps to multiple words across languages (couch, sofa, canapé, divano). Traditional ontologies struggle with these mappings, often forcing a one‑to‑one relationship that does not reflect how language actually works.

This framework separates \*\*concept identity\*\* from \*\*linguistic expression\*\*:

\- \*\*Ontonym\*\* — universal concept container (language‑agnostic)  
\- \*\*Atomonym\*\* — disambiguated string \+ language \+ region  
\- \*\*Isonym\*\* — atomonym that qualifies as a representative of an ontonym

The eidonym tree (hypernym‑hyponym hierarchy) is composed entirely of ontonyms. Isonym clusters attach to ontonym nodes. Users view the tree through a language/region filter, which selects the appropriate isonym (ekpronym) from each cluster.

The framework answers only one question: \*Given that everything is related under entity, how closely are two concepts related?\*

\#\# 3\. The Eidonym Tree

The tree is composed \*\*entirely of ontonyms\*\* — not strings.

\`\`\`  
entity (level 1\)  
│  
├── physical object (level 2\)  
│   ├── vehicle (level 3\)  
│   │   ├── watercraft (level 4\)  
│   │   ├── aircraft (level 4\)  
│   │   └── land vehicle (level 4\)  
│   └── living thing (level 2\)  
│       ├── plant (level 3\)  
│       │   ├── fruit (level 4\)  
│       │   └── vegetable (level 4\)  
│       └── animal (level 3\)  
│           └── mammal (level 4\)  
└── abstract concept (level 2\)  
    └── emotion (level 3\)  
\`\`\`

Each ontonym node has an attached \*\*isonym cluster\*\* containing all atomonyms considered equal representatives of that concept.

\#\# 4\. Isonym Clusters and Ekpronyms

\#\#\# 4.1 Isonym Cluster

An isonym cluster is the set of atomonyms attached to a single ontonym. Membership is determined by a \*\*threshold\*\* (e.g., combined similarity ≥ 0.80).

\*\*Example — Seating Furniture (ONT‑042)\*\*

| Atomonym | Language | Region | Similarity | Isonym? |  
|----------|----------|--------|------------|---------|  
| couch | en | US | 0.95 | yes |  
| sofa | en | UK | 0.94 | yes |  
| settee | en | UK | 0.85 | yes |  
| canapé | fr | FR | 0.96 | yes |  
| divano | it | IT | 0.95 | yes |  
| lounge | en | AU | 0.90 | yes |

\#\#\# 4.2 Ekpronym (Captain per Language)

Each language has a \*\*primary representative\*\* (ekpronym) for each ontonym. The ekpronym is used for:  
\- Displaying the tree in that language  
\- Default labeling in user interfaces  
\- Primary lookup from language to concept

| Language | Ekpronym | Other Isonyms |  
|----------|----------|---------------|  
| English (US) | couch | sofa, settee |  
| English (UK) | sofa | couch, settee |  
| French | canapé | — |  
| Italian | divano | — |

\#\#\# 4.3 Tautonyms (Same Entity)

When two atomonyms refer to the \*\*same specific entity\*\* (Eiffel Tower / Tour Eiffel), they are tautonyms. They share the same ontonym and have structural similarity \= 1.0. The distinction between tautonyms and other isonyms is handled in the atomonym metadata (proper vs common noun).

\#\# 5\. Structural Similarity Metric

The similarity between two nodes is based on the \*\*hodonym\*\* — the path between them.

\#\#\# 5.1 Variables

| Variable | Meaning |  
|----------|---------|  
| \*\*a, b\*\* | Steps from akronym to each node |  
| \*\*|a-b|\*\* | Absolute difference between a and b |  
| \*\*d\*\* | Level of the akronym (lowest common hypernym) |

\#\#\# 5.2 Base Formula

\`\`\`  
strength \= 1 / (1 \+ (1.5ab \+ |a-b|) / (1.1d))  
\`\`\`

Where:  
\- \`1.5\` is lever \*\*e\*\* (weight of descent depth)  
\- \`1.0\` is lever \*\*f\*\* (weight of asymmetry) — not shown as it multiplies |a-b| by 1  
\- \`1.1\` is lever \*\*g\*\* (scaling of peak depth)

These levers are tunable; the defaults (e=1.5, f=1.0, g=1.1) were determined through Monte Carlo simulation.

\#\#\# 5.3 Special Cases

| Case | Rule |  
|------|------|  
| Same node (tautonym / isonym) | strength \= 1.0 |  
| Abstract \+ concrete | strength \= 0.05 |  
| Same eutheonym (ancestor‑descendant) | automatically handled by formula (a or b \= 0\) |

No nested boost is needed; higher \`e\` creates natural separation between parent‑child and siblings.

\#\#\# 5.4 Natural Clusters (Emergent)

| Strength | Relationship | Example |  
|----------|--------------|---------|  
| 1.00 | Same node | couch / sofa, Eiffel Tower / Tour Eiffel |  
| 0.75 | Parent‑child | fruit / orange |  
| 0.64 | Siblings | orange / apple |  
| 0.61 | Mid ancestor | orange / plant |  
| 0.45 | Cousins | orange / potato |  
| 0.41 | Distant ancestor | orange / living thing |  
| 0.24 | Different domains | orange / dog |  
| 0.05 | Abstract / concrete | happiness / hammer |

No categories were forced. They emerged from the structure.

\#\# 6\. Descriptive Similarity (Future Layer)

Structural similarity measures tree geometry. \*\*Descriptive similarity\*\* measures semantic envelope — connotation, register, collocation, cultural framing.

For isonyms (same node), descriptive similarity distinguishes:

| Pair | Structural | Descriptive | Combined |  
|------|------------|-------------|----------|  
| couch / sofa | 1.00 | 0.95 | 0.95 |  
| big / large | 1.00 | 0.85 | 0.85 |  
| house / home | 1.00 | 0.75 | 0.75 |

Descriptive similarity can be computed via:  
\- Axis‑based weighted scoring  
\- Cosine similarity of definition vectors  
\- Human judgment surveys

The two layers combine multiplicatively: \`total \= structural × descriptive\`.

\#\# 7\. Language and Region Filtering

The eidonym tree is universal. Users view it through a \*\*language and region filter\*\*.

\#\#\# 7.1 Filter Hierarchy

| Level | Example |  
|-------|---------|  
| Language | English |  
| Region | United States |  
| Sub‑region (optional) | Midwest |

\#\#\# 7.2 Rendering

For each ontonym node, the system selects the \*\*ekpronym\*\* matching the user's language and region.

\*\*Example — Carbonated Beverage\*\*

| Language/Region | Displayed |  
|----------------|-----------|  
| English (US, Northeast) | soda |  
| English (US, Midwest) | pop |  
| English (UK) | fizzy drink |  
| English (Canada) | pop |  
| French (France) | soda |

\#\#\# 7.3 Lexical Gaps

If a language has no isonym for a concept, the gap can be:  
\- Hidden (user sees only their language)  
\- Shown as a placeholder (\`\[?\]\`)  
\- Shown as a foreign term (\`saudade (pt)\`)

Clicking a gap reveals definition, source language, and cultural context.

\#\# 9\. Comparison to Existing Systems

| Problem | Standard Approach | This Framework |  
|---------|-------------------|----------------|  
| Polyhierarchy | Multiple inheritance | Single inheritance \+ description layer |  
| Synonyms | Duplicate nodes or links | Isonym clusters |  
| Cross‑language | Align WordNet/Wikipedia | Language at atomonym level |  
| Lexical gaps | Ignored or forced translation | Visible gaps |  
| Word sense disambiguation | WSD models | Atomonyms pre‑disambiguate |  
| Semantic similarity | Embeddings (black box) | Structural formula (interpretable) |  
| Abstract/concrete | Separate trees | Single tree \+ rule (0.05) |  
| Named entities | Separate ontology | Tautonym category \+ metadata |  
| Ambiguity | Force resolution | Pearls (preserve) |  
| Scalability | Manual curation | Levers \+ emergent clusters |

\#\# 10\. Conclusion

This framework provides a clean separation between concept identity and linguistic expression. The eidonym tree is composed of ontonyms; isonym clusters attach to nodes; users view the tree through language/region filters. The structural similarity metric is interpretable, tunable, and requires no training data. Special cases are handled with simple rules.

The framework solves classic ontology problems:  
\- \*\*Polyhierarchy\*\* → single inheritance \+ description  
\- \*\*Synonyms\*\* → isonym clusters  
\- \*\*Cross‑language\*\* → language at atomonym level  
\- \*\*Lexical gaps\*\* → visible, not hidden  
\- \*\*Disambiguation\*\* → atomonyms before analysis  
\- \*\*Similarity\*\* → structural formula (a,b,d)  
\- \*\*Abstract/concrete\*\* → rule‑based penalty  
\- \*\*Named entities\*\* → tautonym \+ metadata  
\- \*\*Ambiguity\*\* → pearls  
\- \*\*Scalability\*\* → levers \+ emergent clusters

Everything is related under entity. The question is only how closely. This framework answers that question without forcing categories or black‑box models.
