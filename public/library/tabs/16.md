STAX Artifact Analysis System — Conceptual Overview

This system analyzes student writing in a structured way while preserving the original artifact exactly. The goal is to transform natural language into a fully disambiguated internal representation while still allowing the original text to be perfectly reconstructed.

The system separates the student's writing into two major components: the artifact and the analysis.

The artifact is the original writing submitted by the student. It is stored exactly as written and is never modified. This preserves the authentic record of what the student produced.

The analysis is the structured interpretation of the artifact. It represents the same content as the artifact but transforms the words into atomonyms and adds expression codes that capture the grammatical structure.

The analysis can always reproduce the artifact exactly because every atomonym maps back to a specific string and meaning.

Structural Processing

When an artifact enters the system, it is processed in a series of layers.

Artifact  
→ Paragraphs  
→ Sentences  
→ Expressions  
→ Words

This layered structure allows the system to analyze meaning and grammar separately from the original text.

Paragraph Structure

Artifacts may contain multiple paragraphs. During analysis, paragraph boundaries are preserved so the artifact can be reconstructed exactly.

A paragraph break marker is used internally to represent where paragraphs divide.

Sentence Structure

Each paragraph contains sentences. Sentences are identified and separated during analysis.

Sentences may take several structural forms:

Simple sentence  
Compound sentence  
Composite sentence  
Polymer sentence

In the STAX conceptual analogy:

Words behave like atoms.  
Simple sentences behave like molecules.  
Complex sentences behave like polymers made of multiple molecules.

A simple sentence contains one expression.  
A composite or compound sentence contains multiple expressions connected by conjunctions or embedding.

Expressions

An expression represents the grammatical structure of a clause.

Each expression receives an expression code that describes the structure of the sentence. The expression code determines how the underlying words are interpreted when the sentence is rendered.

Examples of expression types include statements, negative statements, questions, past events, and other grammatical patterns.

For example, the structure for a positive “have” statement and a negative “have” statement can share the same base words but differ only by expression code.

A base expression such as “I have a cookie” can be rendered differently depending on the expression code. One expression code may render it as a positive statement, while another may render it as a negated version such as “I don’t have a cookie.”

This means the expression layer carries important grammatical meaning that is separate from the words themselves.

Words and Atomonyms

Words in the artifact are converted into atomonyms.

An atomonym is a numerical identifier representing a fully disambiguated word. Each atomonym corresponds to a specific string and a specific concept.

In other words, an atomonym represents the combination of a written form and its precise meaning.

For example, the word “bat” may have multiple meanings in English. One meaning refers to a flying mammal, while another refers to a baseball instrument.

Each meaning would receive a different atomonym.

For example, one atomonym might represent the concept of a baseball bat. That atomonym corresponds to the string “bat” and the concept “baseball hitting instrument.”

Because the concept is attached to the number, the atomonym uniquely identifies the meaning of the word.

This makes it possible for the system to analyze student vocabulary knowledge with complete precision.

Context and Peristonyms

Additional contextual information can be associated with words.

For example, a Peristonym may indicate the real-world situation or domain associated with a concept.

If an atomonym represents “bat” as baseball equipment, a Peristonym such as “baseball” can clarify the context in which the word is used.

This enriches the semantic map and helps the system connect words to real situations and domains of knowledge.

Conjunctions

Conjunctions carry meaning and therefore should also be represented as atomonyms rather than raw text.

Conjunctions such as “and,” “but,” “so,” and “because” indicate logical relationships between expressions.

Because conjunctions can sometimes be ambiguous, representing them as atomonyms allows the system to precisely identify the relationship between clauses.

For example, the conjunction “since” may indicate either time or cause. Assigning an atomonym allows the correct interpretation to be recorded.

Phrase Attachment

English contains structural ambiguities related to phrase attachment.

For example, in the sentence “I hit the zombie with the hammer,” the phrase “with the hammer” may attach either to the verb or to the noun.

It could mean that the speaker used a hammer to hit the zombie, or that the zombie possessed the hammer.

This type of ambiguity is known as prepositional phrase attachment ambiguity.

The system resolves this by specifying the attachment point of the phrase.

By default, phrases attach to the verb. If the phrase modifies the noun instead, the analysis explicitly marks that attachment.

This ensures that the meaning of the sentence is fully disambiguated.

Analysis Representation

The analysis is essentially a transformed version of the artifact.

The structure of the sentences is preserved, but the words are replaced with atomonyms and expressions are labeled with expression codes.

The analysis therefore represents the same language but with all meanings clarified.

Because punctuation is preserved, the artifact can always be reproduced exactly.

The analysis therefore serves two purposes. It is both a structured grammatical interpretation and a reversible encoding of the artifact.

Educational Value

Once the artifact has been converted into an analysis, the system can measure student mastery.

The system can evaluate two independent dimensions:

Expression mastery  
Word mastery

Expression mastery evaluates whether the student correctly used grammatical structures.

Word mastery evaluates whether the student demonstrated knowledge of specific vocabulary concepts.

Because atomonyms represent fully disambiguated meanings, the system can determine exactly which word meanings the student understands and which ones they do not.

This creates a powerful framework for tracking language development over time.

Overall Architecture

The final architecture of the system consists of two primary tables.

Artifact table  
Stores the original writing exactly as the student produced it.

Analysis table  
Stores the structured representation of the artifact using expressions and atomonyms.

The analysis references the artifact but does not replace it.

This ensures that the system maintains both a perfect historical record and a precise semantic interpretation.

# **Concept-Grounded Text Architecture**

## **Executive Summary**

This document proposes a language architecture in which **human text is stored as references to disambiguated word entries rather than raw strings**.

Each word entry binds a **string (symbol)** to a **concept (meaning)**, allowing sentences to preserve their exact wording while also embedding explicit semantic identity.

In this system:

• **Strings** are raw language symbols (e.g., “large”, “bat”).  
• **Concepts** represent meaning entities identified by unique IDs.  
• **Words** are bindings between a string and a concept.  
• **Text artifacts** are stored as sequences of **word IDs** rather than raw strings.

Concepts are **identified through relations between strings** (for example: “bat” Hyponym “animal”), which disambiguates meaning and creates a stable concept node.

Once a concept exists, multiple strings (Synonyms or translations) may reference it.

This approach preserves human-readable language while embedding **machine-readable semantic structure directly into stored text**.

The result is text that is:

• **Unambiguous****  
**• **Highly searchable****  
**• **Language-agnostic****  
**• **Compact to store****  
**• **Ready for semantic reasoning**

This architecture separates **symbol, meaning, and structure**, enabling a system where text can evolve from ambiguous strings into **concept-grounded linguistic artifacts**.

# **1. Core Design Principles**

The system separates language into three fundamental layers:

string → symbol  
concept → meaning  
relation → structure

From these primitives emerges a fourth layer:

word = string + concept

A word is therefore not simply a string; it is a **string whose meaning has been identified**.

Strings are the raw symbols entered by users.

Multiple meanings may exist for the same string.

The system must therefore **disambiguate strings to identify concepts**.

# **3. Concepts**

Concepts represent **meaning entities**.

Each concept receives a **unique identifier**.

Example:

Concepts are **language-independent** and may be referenced by strings in different languages.
