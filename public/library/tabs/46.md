\#\# 1. Overview

  

This document specifies the revised algorithm for constructing a complete taxonomic tree rooted at \`entity\`, incorporating axionym nomenclature and a stage-based confirmation lifecycle.

  

The framework is designed for:

\- \*\*Human-AI collaboration\*\* — not fully automated execution

\- \*\*Thought-driven construction\*\* — building by understanding, not scraping

\- \*\*Incremental verification\*\* — nodes progress through confirmation stages

\- \*\*Semantic sequencing\*\* — sibling order defined by axonyms at hypernym level

\#\# 2. Data Structures

  

\#\#\# 2.1 Eidonym Table

  

The core table storing concept nodes. Each row represents one eidonym.

  

| Field | Axionym | Type | Description |

|-------|---------|------|-------------|

| atomonym | Atomonym | binary (32 bytes) or string | Unique identifier; binary recommended for database, simple codes (e001) for manual entry |

| nemonym | Nemonym | string | The word or phrase (e.g., "dog", "time", "physical\_object") |

| hypernym | Hypernym | atomonym | Parent eidonym (NULL for root) |

| koinonym | Koinonym | integer (1-5) | Commonality frequency band (1=ultra-common, 5=rare) |xxx

| protonym | Protonym | atomonym | Left sibling (NULL if leftmost) |

| axonym | Axonym | atomonym | Reference to Axonym table (NULL = no enforced order) |

| stadionym | Stadionym | integer (0-4) | Confirmation stage (see Section 2.3) |

  

\#\#\# 2.2 Axonym Table

  

Stores sequencing axes for sibling ordering.

  

| Field | Type | Description |

|-------|------|-------------|

| atomonym | binary or string | Unique identifier (ax001, etc.) |

| nemonym | string | Axis name (e.g., "chronological", "magnitude", "temperature") |

| description | text | Orientation notes (e.g., "cold → hot", "past → future") |

  

\#\#\# 2.3 Stadionym Stages

  

| Value | Stage | Meaning | Next Action |

|-------|-------|---------|-------------|

| 0 | flagged | Needs review, paused | Resolve issue, move to 1 or discard |

| 1 | nominated | Candidate identified, parent set | Run scoponym check |

| 2 | scoped | Scoponym passed, parent confirmed | Run isonym check |

| 3 | isonym\_checked | Siblings identified, axonym tentative | Confirm axonym (or NULL) |

| 4 | confirmed | Fully verified, ready for children | Generate children (new rows, stadionym=1) |

  

\#\#\# 2.4 Koinonym Bands

  

| Band | Koinonym | Frequency Rank | Examples |

|------|----------|----------------|----------|

| 1 | Koinotatos | 1-100 | time, day, year, person |

| 2 | Koinos | 101-1,000 | thing, being, event, place |

| 3 | Metrios | 1,001-5,000 | concept, relation, property |

| 4 | Spanios | 5,001-20,000 | era, epoch, millennium |

| 5 | Spaniotatos | 20,000+ | eon, picosecond, ontonym |

\#\# 3. The Algorithm

  

\#\#\# 3.1 Core Principle: Stage-Based Expansion

  

Instead of a queue, the system processes eidonyms by \*\*stadionym priority\*\*:

  

| Priority | Stadionym | Action |

|----------|-----------|--------|

| 1 | 0 | Resolve flagged issues (human/AI review) |

| 2 | 1 | Run scoponym check |

| 3 | 2 | Run isonym check |

| 4 | 3 | Confirm axonym (or set NULL) |

| 5 | 4 | Generate children (new eidonyms at stadionym=1) |

  

\#\#\# 3.2 Scoponym Check (Stadionym 1 → 2)

  

\`\`\`

function scoponym\_check(eidonym):

    \# Verify that eidonym is a direct hyponym of its hypernym

    

    candidates = generate\_hyponym\_candidates(eidonym.hypernym.nemonym)

    

    if eidonym.nemonym in candidates:

        \# Check for intermediates

        intermediate = find\_intermediate(eidonym.nemonym, eidonym.hypernym.nemonym)

        

        if intermediate exists:

            \# Reparent to intermediate

            eidonym.hypernym = intermediate

            return "reparented"

        else:

            eidonym.stadionym = 2

            return "verified"

    else:

        eidonym.stadionym = 0

        eidonym.notes = "Scoponym failed: not a hyponym"

        return "failed"

\`\`\`

  

\#\#\# 3.3 Isonym Check (Stadionym 2 → 3)

  

\`\`\`

function isonym\_check(eidonym):

    \# Identify all siblings under the same hypernym

    

    siblings = get\_children(eidonym.hypernym)

    missing = detect\_missing\_siblings(eidonym.hypernym, siblings)

    

    if missing:

        for m in missing:

            create\_provisional\_eidonym(m, eidonym.hypernym)

        eidonym.stadionym = 0

        eidonym.notes = "Missing siblings detected"

        return "missing\_siblings"

    

    \# Detect natural ordering axis

    axis = detect\_natural\_axis(siblings)

    if axis:

        eidonym.hypernym.axonym = axis

        sequence\_siblings(siblings, axis)  \# sets protonym chain

    

    eidonym.stadionym = 3

    return "completed"

\`\`\`

  

\#\#\# 3.4 Axonym Confirmation (Stadionym 3 → 4)

  

\`\`\`

function confirm\_axonym(eidonym):

    \# Finalize axonym or confirm NULL

    

    if eidonym.axonym is not NULL:

        \# Verify axis applies to all siblings

        if axis\_valid (eidonym.axonym, get\_children(eidonym)):

            eidonym.stadionym = 4

            return "confirmed"

        else:

            eidonym.stadionym = 0

            eidonym.notes = "Axonym validation failed"

            return "failed"

    else:

        \# Explicitly confirm no enforced order

        eidonym.stadionym = 4

        return "confirmed"

\`\`\`

  

\#\#\# 3.5 Generate Children (Stadionym 4 → new rows)

  

\`\`\`

function generate\_children(eidonym):

    \# Create child eidonyms from known hyponyms

    

    candidates = generate\_hyponym\_candidates(eidonym.nemonym)

    

    for candidate in candidates:

        if scoponym\_check(candidate, eidonym.nemonym) == "direct":

            child = create\_eidonym(

                nemonym = candidate,

                hypernym = eidonym.atomonym,

                koinonym = rank\_to\_band(get\_frequency\_rank(candidate)),

                stadionym = 1

            )

    

    eidonym.stadionym = 4  \# remains confirmed, children now exist

\`\`\`

\#\# 5. Quality Control

  

\#\#\# 5.1 Stage Distribution

  

Healthy tree should show:

\- Few at 0 (flagged) — ideally zero

\- Growing numbers at 1, 2, 3 as construction proceeds

\- Expanding base at 4 (confirmed) that spawns new 1s

  

\#\#\# 5.2 Depth Consistency

  

Periodically verify that all eidonyms with hypernym have hypernym.stadionym \>= 3 (parent confirmed before children)

  

\#\#\# 5.3 Protonym Chain Integrity

  

Verify that protonym chains:

\- Are acyclic

\- Have exactly one NULL per sibling group

\- Cover all siblings (if axonym set)

\#\# 8. Implementation Notes

  

\- \*\*Start with Google Sheets\*\* for manual construction — use simple atomonyms (e001, e002)

\- \*\*Migrate to database\*\* when tree reaches \~500 nodes

\- \*\*Use binary atomonyms\*\* in production for performance

\- \*\*Human scoponym\*\* during manual phase — you are the verification mechanism

\- \*\*Flag (stadionym=0)\*\* whenever uncertainty arises — don't force correctness
