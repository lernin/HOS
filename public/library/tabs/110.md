# Is it a type?

\# Ontology Framework for Vehicle Classification  
\#\# A Reality-Grounded System for Type Determination

\---

\#\#\# 1\. Core Definitions

\*\*Artifact\*\*: A human-made object intentionally created for a purpose.

\*\*Vehicle\*\*: An artifact whose primary function is locomotion (controlled, navigational movement through an environment).

\*\*Locomotion\*\*: Controlled, directed movement of an entity from one position to another, characterized by navigational displacement.

\---

\#\#\# 2\. The Type vs. Role Distinction

| Concept | Definition | Example |  
|---------|------------|---------|  
| \*\*Type\*\* | What something fundamentally \*is\* (stable identity) | Car → vehicle; Horse → animal |  
| \*\*Role\*\* | What something \*does\* in a specific context | Horse in riding event → transport role |

\*\*Golden Rule\*\*: Role does not override type.

\*\*Courtroom Test\*\*: If two classifications compete, the one that sounds universally, immediately correct wins.  
\- "A horse is a mammal" → ✅  
\- "A horse is a vehicle" → ❌

\---

\#\#\# 3\. Type Membership Gate (Step 1\)

Before any axis analysis, ask:

\> \*"Is this object fundamentally a kind of \[TARGET TYPE\]?"\*

\- \*\*NO\*\* → Stop. Do not proceed.  
\- \*\*YES\*\* → Continue to axis evaluation.

\*\*Purpose\*\*: Prevents false positives (skis, skates, forklifts) from being evaluated as vehicles.

\---

\#\#\# 4\. Primary Function \= Dominant Real-World Use

Type is determined by what an object is \*primarily used for\*, not what it \*can do\*.

\*\*Event Analysis Method\*\*:  
1\. Brainstorm all real-world events involving the object  
2\. Estimate distribution of uses  
3\. Apply threshold rule

\*\*30% Threshold Rule\*\*:  
\- If a function appears in ≥30% of real-world events → qualifies as a primary function  
\- If a function appears in \<30% → not identity-defining

\*\*Examples\*\*:  
| Object | Transport Use | Verdict |  
|--------|---------------|--------|  
| Car | \~100% | ✅ Vehicle |  
| Canoe | \~90% | ✅ Vehicle |  
| Skateboard | \~30-50% | ⚠️ Borderline / Weak vehicle |  
| Skates | \~3% | ❌ Not vehicle |  
| Skis | \~0.3% | ❌ Not vehicle |

\---

\#\#\# 5\. Axis Evaluation (Step 2\)

Once type membership is confirmed, evaluate axes.

\*\*Universal Question\*\*:

\> \*"For the axis of \[AXIS NAME\] (\[VALUE 1, VALUE 2, ...\]), which value(s) are essential to what this object is as a \[TYPE\]?"\*

\*\*Interpretation\*\*:  
\- One value → assign to that category  
\- Multiple values → candidate hybrid → run Emergent Kind Test  
\- No values → object is not a valid member of the target type

\---

\#\#\# 6\. Medium Axis (Vehicle-Specific)

The medium axis uses four primary values: Land, Water, Air, Space.

\*\*Application\*\*:

| Object | Essential Medium(s) | Classification |  
|--------|---------------------|----------------|  
| Boat | Water | Watercraft |  
| Car | Land | Land vehicle |  
| Hovercraft | Land \+ Water | Amphibious vehicle |  
| Spaceplane | Air \+ Space | Aerospace vehicle |  
| Drone | Air | Aircraft |

\---

\#\#\# 7\. Hybrid Detection

\*\*Rule\*\*: If an object requires multiple axis values to define its essential identity, it creates a new hybrid type.

\*\*Emergent Kind Test\*\*:  
\- If members fit cleanly into existing categories → attribute, not type  
\- If members do NOT fit cleanly → emergent kind → new type

\*\*Examples\*\*:  
\- Hovercraft → does not fit cleanly in Land or Water → Amphibious vehicle ✅  
\- Spaceplane → does not fit cleanly in Air or Space → Aerospace vehicle ✅

\---

\#\#\# 8\. Multi-Type Objects

Some objects legitimately belong to multiple types when they meet the threshold for multiple functions.

\*\*Examples\*\*:  
| Object | Type 1 | Type 2 | Type 3 |  
|--------|--------|--------|--------|  
| RV / Camper van | Vehicle | Dwelling | — |  
| Smartphone | Communication device | Computer | Camera |  
| Drone (delivery) | Vehicle | — | — |  
| Drone (camera) | Vehicle | Sensor platform | — |

\---

\#\#\# 9\. What Is NOT a Vehicle

| Category | Examples | Reason |  
|----------|----------|--------|  
| Body-worn movement aids | Skates, skis | No independent locomotion system; activity-based |  
| Animals | Horse, camel | Biological organisms, not artifacts |  
| Tools with incidental movement | Forklift | Primary function ≠ locomotion |  
| Natural objects | Leaf, iceberg | Not artifacts; movement is incidental |

\---

\#\#\# 10\. Vehicle Strength Spectrum

Vehicles exist on a spectrum based on how dominant locomotion is as a primary function:

| Strength | Examples | Transport Usage |  
|----------|----------|-----------------|  
| Strong vehicle | Car, boat, airplane | 90-100% |  
| Clear vehicle | Bicycle, canoe, delivery drone | 70-90% |  
| Weak vehicle | Skateboard, kick scooter | 30-50% |  
| Borderline | Roller skates (some contexts) | 10-30% |  
| Not vehicle | Ice skates, skis | \<10% |

\---

\#\#\# 11\. Summary of Key Rules

| Rule | Statement |  
|------|-----------|  
| \*\*Role vs. Type\*\* | Role does not override type |  
| \*\*Type Gate\*\* | Verify type membership before axis analysis |  
| \*\*Primary Function\*\* | Determined by dominant real-world use, not capability |  
| \*\*Threshold\*\* | ≥30% usage \= qualifies as primary function |  
| \*\*Hybrid\*\* | Multiple essential axis values → new type |  
| \*\*Multi-Type\*\* | Objects can belong to multiple types if thresholds are met |  
| \*\*Vehicle Definition\*\* | Artifact whose primary function is locomotion |

\---

\#\#\# 12\. Quick Reference: Vehicle Test Flow

\`\`\`  
1\. Is it an artifact?   
   NO → Stop  
   YES → Continue

2\. Is locomotion its primary function? (Use event analysis \+ 30% threshold)  
   NO → Stop  
   YES → Continue

3\. Which medium(s) are essential to its operation?  
   One → Assign to that category  
   Multiple → Create hybrid type  
\`\`\`
