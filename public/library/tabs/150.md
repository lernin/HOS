# **Core Idea**

A child submits a piece of writing (“artifact”).

The system:

1. analyzes the writing linguistically,  
2. identifies vocabulary and structures,  
3. detects corrections and weaknesses,  
4. stores evidence of learning,  
5. tracks long-term mastery growth over time.

The goal is NOT simply grammar correction.

The goal is:

longitudinal language acquisition tracking

This creates:

* vocabulary growth tracking,  
* grammatical development tracking,  
* semantic understanding tracking,  
* personalized learning reinforcement.

---

# **Fundamental Principle**

The artifact should NOT be analyzed sentence-by-sentence independently.

Instead:

artifact  
→ normalized linguistic inventory  
→ semantic analysis  
→ evidence tracking

This avoids massive redundancy.

# **3\. Tokenization**

Break sentences into tokens.

Example:

Each token receives:

* token ID,  
* position,  
* sentence index.

Example:

| Token ID | Token | Position |
| ----- | ----- | ----- |
| 1 | I | 1 |
| 2 | drinked | 2 |
| 3 | milk | 3 |

This preserves:

* order,  
* context,  
* frequency,  
* evidence mapping.

# **6\. STAX Preprocessing Layer**

Before standard analysis, STAX-specific structures may be identified.

Examples:

* bridges,  
* gates,  
* time markers,  
* STAX semantic categories.

Example:

| Phrase | STAX Category |
| ----- | ----- |
| want to | bridge |
| have to | gate |
| tomorrow | time marker |

These may bypass later analysis stages.

---

# **7\. Deduplicated Lexical Inventory**

The system creates a unique inventory of lexical items.

Example:

drink \+ VERB  
milk \+ NOUN  
cold \+ ADJECTIVE

This prevents repeated expensive lookups.

Important distinction:

| Concept | Meaning |
| ----- | ----- |
| Type | unique lexical item |
| Token | actual occurrence |

Example:

milk milk milk

* 1 lexical type  
* 3 lexical tokens

The system stores BOTH.

# **Important WSD Principle**

WordNet itself is stable.

The ambiguity comes from:

* context interpretation,  
* disambiguation algorithms.

Therefore:

WSD \= probabilistic

The system should store confidence scores.

Example:

{  
  "sense": "milk.n.01",  
  "confidence": 0.91  
}

---

# **9\. Token-to-Sense Mapping**

After analysis, each token instance reconnects to the selected sense.

Example:

| Token | Sense |
| ----- | ----- |
| milk (token \#3) | milk.n.01 |
| milk (token \#8) | milk.n.01 |

This preserves:

* repetition frequency,  
* contextual evidence,  
* longitudinal usage data.

---

# **Proposed Correction Symbols**

## **Spelling Error**

\~S

Example:

drinked \~S→ drank

---

## **Grammar Error**

\~G

Example:

I jumping \~G→ I am jumping

---

## **Word Choice Error**

\~W

Example:

good \~W→ delicious

---

## **Omitted Word**

\~O

Example:

I went store  
\~O→ to the

---

## **Punctuation Error**

\~P

Example:

hello \~P→ hello.

---

## **Capitalization Error**

\~C

Example:

london \~C→ London

---

## **Tense / Consistency Error**

\~T

Example:

Yesterday I jump  
\~T→ jumped

---

# **Suggested Internal Annotation Structure**

Example:

{  
  "original": "drinked",  
  "corrected": "drank",  
  "error\_type": "spelling",  
  "token\_position": 2  
}

Or:

{  
  "original": null,  
  "inserted": "to the",  
  "error\_type": "omission"  
}

# **13\. Longitudinal Mastery Tracking**

The system tracks:

* successful uses,  
* failed uses,  
* context diversity,  
* recency,  
* stability over time.

Important insight:

frequency alone is not enough

Context diversity matters.

Example:

Weak evidence:

milk milk milk milk

Strong evidence:

I drank milk.  
Chocolate milk tastes sweet.  
The milk was cold.

This demonstrates:

* broader semantic understanding,  
* flexible usage,  
* deeper mastery.

Appendix — Hidden Annotation Marker System

To support invisible internal correction tracking, the STAX system may use a rare Unicode marker character as an internal annotation trigger.

Example candidate markers:

𐤀

𐤌

𐤒

These symbols originate from the ancient Phoenician alphabet and are extremely unlikely to appear naturally in student writing.

The purpose of these markers is to:

create unambiguous machine-readable correction annotations,

avoid collisions with ordinary language,

support hidden backend linguistic tracking,

remain invisible or filtered from student-facing output.

Example internal annotations:

𐤀S \= spelling correction

𐤀G \= grammar correction

𐤀W \= word choice correction

𐤀O \= omission

𐤀T \= tense inconsistency

Example:

drinked 𐤀S→ drank

or

I went store 𐤀O→ to the

These annotations are intended primarily for:

backend linguistic analysis,

mastery tracking,

learner corpus construction,

AI training and feedback systems.

Students would normally see only the corrected final text, while the annotation layer remains internal to the STAX analysis engine.
