# Table Presence  

## **Relation Status**

  

Axionym — primitive relations family

  ↓

Deiconym  (stored relation indicated with bold)

   ↓

Deronym   (derived relation)

In this framework, relations are divided into two types depending on how they are used in the system.

Some relations are **stored directly in the database tables**. These relations form the operational structure of the system and are written in **bold** to make them easy to identify.

These stored relations are called **Deiconyms**.

Other relations are **not stored directly**, but can be **derived logically from the stored relations**. These derived relations help explain the system and make the relationships easier for humans to understand.

These derived relations are called **Deronyms**.

In simple terms:

**Deiconym** — a relation that is stored in the database.  
 **Deronym** — a relation that can be derived from a stored relation.

This distinction keeps the database structure **simple and efficient**, while still allowing the framework to describe a richer set of conceptual relationships.
