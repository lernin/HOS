# Here is \*\*V22

Here is \*\*V22.0\*\* — combining the deterministic state machine structure of V21.0 with the completeness, validation loops, and conceptual clarity of V20.8.

\---

\# ONTOLOGY ENGINE — V22.0  
\#\# EXPLICIT STATE MACHINE WITH MANDATORY CHECKPOINTS \+ EXHAUSTIVE VALIDATION

\---

\#\# STATE 1: DISAMBIGUATE

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | String |  
| \*\*Output\*\* | Antomonym(s) with unique\_id, canonical\_name |  
| \*\*Action\*\* | Resolve all polysemy. Map string → one or more antomonyms. Each antomonym has exactly one hypernym, zero or more hyponyms, canonical name, and associated attributes. |  
| \*\*Next\*\* | STATE\_2 |

\*\*Principle:\*\* Disambiguation precedes all analysis. The tree is populated by unique identifiers for disambiguated real kinds, not ambiguous strings.

\---

\#\# STATE 2: IDENTIFY\_ROOT\_GOVERNING\_CONSTRAINT

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | Antomonym |  
| \*\*Action\*\* | Determine the single most fundamental governing constraint for the concept. Ask: "What one constraint determines the majority of the thing's structure, composition, and behavior?" |  
| \*\*Output\*\* | root\_split\_candidate |  
| \*\*Next\*\* | STATE\_3 |

\*\*Examples:\*\* Vehicle → medium of operation; Food → processing/structural transformation; Entity → physical vs abstract existence.

\---

\#\# STATE 3: GENERATE\_ARRAY

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | Current node |  
| \*\*Action\*\* | Identify all possible axes (governing constraints, structural dimensions) relevant to the current node. For each axis, identify its possible values. Populate n-dimensional array to reveal all stable, real kinds at every intersection. |  
| \*\*Output\*\* | Complete set of stable\_real\_kinds at all intersections, including hybrids |  
| \*\*Next\*\* | STATE\_4 |

\*\*Principle:\*\* The array is the source of truth for discovery. Do not finalize any hierarchy until the array is complete. Hybrids are legitimate real kinds occupying intersections across multiple axes — not failures to classify.

\---

\#\# STATE 4: EXTRACT\_CANDIDATES

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | stable\_real\_kinds from STATE\_3 |  
| \*\*Action\*\* | For current node, list all stable\_real\_kinds that could be direct hyponyms |  
| \*\*Output\*\* | candidate\_set |  
| \*\*Next\*\* | STATE\_5 |

\---

\#\# STATE 5: TERMINATION GATE — FIRST CHECK

| Condition | Action |  
|-----------|--------|  
| candidate\_set is empty | node.leaf \= true → goto STATE\_14 (TERMINATE\_NODE) |  
| candidate\_set is not empty | next → STATE\_6 |

\---

\#\# STATE 6: APPLY\_EMERGENT\_KIND TEST (MEMBER-FORCED CATEGORY TEST)

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | candidate\_set |  
| \*\*Action\*\* | For each candidate, examine its members. Ask: "Do the members of this candidate category fit cleanly into existing categories, or do they force the creation of a new category because no existing category accommodates them?" |  
| \*\*Decision\*\* | If members fit cleanly into existing categories → mark candidate \= ATTRIBUTE, remove from candidate\_set |  
| | If members do NOT fit into existing categories → mark candidate \= CANDIDATE\_TYPE (emergent kind) |  
| \*\*Next\*\* | If candidate\_set is empty after test → goto STATE\_14 |  
| | Else → STATE\_7 |

\*\*Test Case — Amphibious vehicle:\*\* Members (hovercraft, amphibious car) do NOT fit cleanly into Land vehicle or Watercraft → EMERGENT KIND → TYPE

\*\*Test Case — Keyboard instrument:\*\* Members (piano, pipe organ, synthesizer) each fit cleanly into existing categories → ATTRIBUTE (interface), NOT a type

\---

\#\# STATE 7: APPLY\_TYPE\_CRITERIA (CORE RULE)

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | candidate\_set |  
| \*\*Action\*\* | For each candidate, test against core type criteria. A valid TYPE must change what the thing IS based on: structure, composition, causal mechanism, governing constraints, persistence/failure conditions. |

\#\#\# Rejection Rules (remove candidates that are):  
| Reject If Candidate Is |  
|-----------------------|  
| Description (red, fast, loud) |  
| State (broken, old, new) |  
| Role/Purpose (transportation device, writing tool) |  
| Context/Location (indoor, outdoor, urban) |  
| Ownership (mine, yours, rental) |  
| Temporary condition (wet, damaged, activated) |

| Decision | Action |  
|----------|--------|  
| Candidate fails criteria OR matches rejection rule | Mark \= ATTRIBUTE, remove from candidate\_set |  
| Candidate passes criteria | Keep as CANDIDATE\_TYPE |

| \*\*Next\*\* | If candidate\_set is empty → goto STATE\_14 |  
| | Else → STATE\_8 |

\---

\#\# STATE 8: APPLY\_SIGNIFICANCE\_FILTER

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | candidate\_set |  
| \*\*Action\*\* | For each candidate, test: is it true, relevant, significant, and sufficient to complete the level? |  
| \*\*Decision\*\* | If candidate lacks ANY of these → remove from candidate\_set |  
| \*\*Next\*\* | If candidate\_set is empty → goto STATE\_14 |  
| | Else → STATE\_9 |

\---

\#\# STATE 9: APPLY\_SINGLE INHERITANCE & DIRECTNESS

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | candidate\_set, current node |  
| \*\*Action\*\* | Every antomonym has exactly one parent. No polyhierarchy, no multiple inheritance. Hybrids that passed the Emergent Kind Test are placed under one parent — determined by their primary governing constraint or the coherent intermediate category they form. |  
| \*\*Additional Action\*\* | Insert missing intermediate layers. Never skip levels. If a kind has subtypes that share a coherent intermediate category, promote that category as a direct hyponym before listing its children. |  
| \*\*Output\*\* | candidate\_set with parent assignments, intermediate layers inserted |  
| \*\*Next\*\* | STATE\_10 |

\---

\#\# STATE 10: APPLY\_CANONICAL\_NAMING

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | candidate\_set |  
| \*\*Action\*\* | Use real-world category names. Prefer established expert terms, standalone nouns, simpler widely understood terms when they capture the distinction cleanly. |  
| \*\*Avoid\*\* | Repeating parent (marsupial mammal), descriptive phrases when a name exists, invented labels, unnecessary technical terms when simpler language suffices. |  
| \*\*Output\*\* | candidate\_set with canonical names |  
| \*\*Next\*\* | STATE\_11 |

\---

\#\# STATE 11: EXHAUSTIVE TESTING LOOP (VALIDATION GATE)

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | candidate\_set, current node, original array from STATE\_3 |  
| \*\*Action\*\* | Before finalizing the split at this node: |

\#\#\# Procedure:  
1\. Generate the candidate set using the current axis model  
2\. Test exhaustively: For each stable, real kind in the domain under this node, does it fit cleanly into one candidate?  
3\. Identify escapees: Kinds that don't fit are evidence that:  
   \- the axis set is incomplete  
   \- a hybrid category is required  
   \- the candidate split is wrong  
4\. Iterate: Add axes, adjust, or promote hybrids until all stable kinds are accounted for  
5\. Do not finalize until the candidate set accounts for all significant, stable kinds without forcing misfits

| Decision | Action |  
|----------|--------|  
| Escapees found, requiring axis addition or candidate adjustment | Return to STATE\_3 (GENERATE\_ARRAY) with refined axes |  
| All stable kinds accounted for without forced fits | Proceed to STATE\_12 |

\---

\#\# STATE 12: CONVERGENCE CHECK (VALIDATION GATE)

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | candidate\_set, current node, entire hierarchy built so far |  
| \*\*Action\*\* | Check if the current node's hierarchy is converged: |

\#\#\# Convergence Criteria:  
| Criterion | Requirement |  
|-----------|-------------|  
| Minimal | No unnecessary nodes |  
| Stable | Consistent across use cases |  
| Non-overlapping | No sibling categories that overlap in meaning |  
| Reality-grounded | Every node corresponds to a real kind in the world |  
| Canonically named | Using appropriate, clear terminology |

| Decision | Action |  
|----------|--------|  
| Not converged | Return to appropriate earlier state (typically STATE\_3 with refined approach) |  
| Converged | Proceed to STATE\_13 |

\---

\#\# STATE 13: OUTPUT

| Property | Value |  
|----------|------|  
| \*\*Input\*\* | candidate\_set |  
| \*\*Action\*\* | Provide candidate\_set as direct hyponyms of current node |  
| \*\*Recursion\*\* | For each candidate in candidate\_set, return to STATE\_2 with candidate as new input |  
| \*\*Next\*\* | Recursive descent continues until all branches terminate |

\---

\#\# STATE 14: TERMINATE\_NODE

| Property | Value |  
|----------|------|  
| \*\*Action\*\* | Output nothing for this branch |  
| \*\*Result\*\* | Branch ends. Node is leaf. |

\---

\# FINAL CHECK

Each type output by STATE\_13 must satisfy:

| Requirement |  
|-------------|  
| Structurally/mechanistically distinct |  
| Not role/context/state-based |  
| A real kind (represented by an antomonym) |  
| Derived from governing constraint(s) via array |  
| Validated by Emergent Kind Test — members do NOT fit cleanly into existing categories |  
| Named using clear, appropriate terms |  
| Significant enough to list |  
| Sufficient to complete the level |  
| Accounted for in exhaustive test — no forced fits |  
| Single parent — no polyhierarchy |

Attributes are documented separately for faceting.
