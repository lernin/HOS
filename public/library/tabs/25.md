# Primary Dualities  

### **Core Dualities in the System**

As the framework develops, several **fundamental dualities** appear.  
 These dualities help clarify how concepts and relations function within the system.

### **1. Entity Duality**

Every entity in the system is one of two kinds:

**Eidonym** — conceptual class  
 **Idionym** — concrete instance

Examples

Eidonym

animal

dog

poodle

  

Idionym

Fido

Lassie

So every object in the database ultimately belongs to one of these two categories.

Eidonym  → conceptual class

Idionym  → instance of a class

### **2. Relation Duality**

Every relation in the system is one of two kinds:

**Deiconym** — relation explicitly stored in the database  
 **Deronym** — relation that can be derived from stored relations

Example

Stored

dog → animal      (Hyponym)

  

Derived

animal → dog      (Hypernym)

So every relation can be understood as either:

Deiconym  → stored relation

Deronym   → derived relation

### **Summary**

The system therefore operates around two fundamental structural distinctions:

Entities

Eidonym / Idionym

  

Relations

Deiconym / Deronym

These dualities simplify the architecture by separating:

• conceptual classes vs concrete instances  
 • stored relations vs derived relations
