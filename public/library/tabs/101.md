\---

\# A Structured Method for Conceptual Similarity Measurement  
\#\# Defining the Isonym Threshold Through Axes, Weights, and Eidonomic Context

\*\*Version 1.0\*\*  
Ashley — Ontology Engine V20.7

\---

\#\# Abstract

This paper presents a deterministic, interpretable method for measuring conceptual similarity between two autonyms. Unlike black-box embedding models, this approach uses explicitly defined axes of consideration, weighted by significance, and grounded in the eidonomic structure of hypernym/hyponym relationships. The method produces a similarity score that determines whether two autonyms qualify as isonyms — members of the same ontonym — or are better classified as adelphonyms (siblings), cousins, or unrelated concepts.

The system acknowledges that meaning is inherently fuzzy and manages this fuzz through arbitrated thresholds rather than pretending sharp boundaries exist.

\---

\#\# 1\. Introduction

Standard approaches to semantic similarity rely on high-dimensional embeddings trained on massive corpora. While powerful, these models are:

\- \*\*Uninterpretable\*\* — the dimensions have no explicit meaning  
\- \*\*Non-deterministic\*\* — results cannot be traced to specific features  
\- \*\*Culturally flattened\*\* — nuance across languages and contexts is lost  
\- \*\*Static\*\* — meaning evolution over time is not captured

This paper proposes an alternative: a structured, explicit similarity method built on:

1\. \*\*Eidonomic analysis\*\* — hypernym/hyponym relationships establish structural context  
2\. \*\*Axis selection\*\* — relevant dimensions of comparison are explicitly defined  
3\. \*\*Weighting\*\* — significance of each axis is assigned  
4\. \*\*Arbitrated thresholds\*\* — boundaries are set by the system designer, not hidden in training data

\---

\#\# 2\. Core Definitions

\#\#\# 2.1 Ontonym  
A universal concept container, language-agnostic, identified by a unique ID. An ontonym represents a fuzzy cluster of meanings that are close enough to be considered the same concept for the purposes of the ontology.

\#\#\# 2.2 Atomonym  
A disambiguated string associated with a specific language and, optionally, a region. Each atomonym contains:  
\- Unique identifier  
\- String value  
\- Language tag (e.g., en, fr, ko)  
\- Definition vector (axes \+ weights \+ values)  
\- Creation date  
\- Reference to its ontonym

\#\#\# 2.3 Isonym  
An autonym that exceeds the conceptual similarity threshold and is therefore considered a member of its ontonym. Isonyms are \*\*equal representatives\*\* of the same concept.

\#\#\# 2.4 Adelphonym  
Two autonyms that share the same hypernym but do not exceed the isonym threshold. They are \*\*siblings\*\* — distinct concepts under a common parent.

\#\#\# 2.5 Eidonym Tree  
The hypernym/hyponym hierarchy. This structure is consulted first to establish the relationship type between two autonyms before similarity is measured.

\---

\#\# 3\. The Similarity Method

\#\#\# 3.1 Step 1 — Eidonomic Context

Before any similarity calculation, the system determines the relationship between the two autonyms by tracing their hypernym paths.

| Path Relationship | Interpretation |  
|-------------------|----------------|  
| Same node | Candidate for isonym |  
| Same hypernym (different nodes) | Adelphonyms (siblings) |  
| Different branches | Cousins or unrelated |  
| No shared path | Different domains |

This step ensures that similarity measurement is applied to the correct relationship type.

\#\#\# 3.2 Step 2 — Axis Selection

For each comparison, the system selects a set of axes that are \*\*relevant, significant, and sufficient\*\* to distinguish the two autonyms.

\*\*Criteria:\*\*  
\- \*\*Relevant\*\* — Does this axis help distinguish the concepts?  
\- \*\*Significant\*\* — Does this axis matter for how people understand the concepts?  
\- \*\*Sufficient\*\* — Do these axes together capture the essential differences?

Example axes for food items:  
\- Category (dessert, savory, beverage)  
\- Structure (layered, crusted, composed)  
\- Preparation (baked, fried, raw)  
\- Occasion (celebration, everyday)  
\- Base (flour, dairy, fruit, meat)

\#\#\# 3.3 Step 3 — Value Assignment

Each autonym is assigned values along the selected axes.

| Axis | Cake | Pie |  
|------|------|-----|  
| Category | dessert | dessert |  
| Structure | layered/frosted | crust \+ filling |  
| Preparation | baked | baked |  
| Occasion | celebration | celebration or casual |  
| Base | flour | flour \+ fruit |

Values may be binary (0/1), scaled (0–1), or categorical (converted to numeric).

\#\#\# 3.4 Step 4 — Match Scoring

For each axis, the system calculates a match score:

| Match | Score | Definition |  
|-------|-------|------------|  
| Same | 1.0 | Values are identical |  
| Similar | 0.5 | Values are comparable but not identical |  
| Different | 0.0 | Values are unrelated or opposite |

\#\#\# 3.5 Step 5 — Weight Assignment

Each axis receives a weight reflecting its significance for the comparison.

| Axis | Weight | Justification |  
|------|--------|---------------|  
| Category | 3 | Most fundamental — dessert vs savory changes everything |  
| Structure | 3 | Primary physical distinction |  
| Preparation | 2 | Important for culinary classification |  
| Occasion | 1 | Culturally significant but not definitional |  
| Base | 1 | Matters for dietary, not primary |

\#\#\# 3.6 Step 6 — Weighted Similarity Calculation

The similarity score is calculated as:

\`\`\`  
Similarity \= Σ(weight × match) ÷ Σ(weight)  
\`\`\`

\*\*Example — Cake vs Pie:\*\*

| Axis | Weight | Match | Weighted |  
|------|--------|-------|---------|  
| Category | 3 | 1.0 | 3.0 |  
| Structure | 3 | 0.5 | 1.5 |  
| Preparation | 2 | 1.0 | 2.0 |  
| Occasion | 1 | 0.5 | 0.5 |  
| Base | 1 | 0.5 | 0.5 |

Σ weights \= 10  
Σ weighted \= 7.5

\*\*Similarity \= 0.75\*\*

\---

\#\# 4\. Threshold System

The resulting similarity score is interpreted according to arbitrated thresholds:

| Score | Category | Status |  
|-------|----------|--------|  
| 1.00 | Identical | Same autonym |  
| 0.95–0.99 | Core Isonym | Automatic inclusion in ontonym |  
| 0.85–0.94 | Strong Isonym | Inclusion in ontonym |  
| 0.75–0.84 | Edge Isonym | Review / flag for inclusion |  
| 0.60–0.74 | Sibling Concepts | Adelphonyms — same hypernym, distinct |  
| 0.40–0.59 | Cousins | Related but distant |  
| 0.20–0.39 | Weak Relation | Loosely connected |  
| \<0.20 | Unrelated | Different domains |

\---

\#\# 5\. Handling Same Referent with Different Semantics

When two autonyms refer to the same entity but carry different semantic envelopes (e.g., "Eiffel Tower" vs "Tour Eiffel"), the method reveals the nuance:

| Comparison | Referent Identity | Similarity | Classification |  
|------------|-------------------|------------|----------------|  
| ANT-001 vs ANT-002 | Same tower | \~0.92 | Core isonyms with cultural nuance |

The similarity score is high enough for isonym inclusion but not perfect, reflecting the different cultural payloads.

\---

\#\# 6\. Meaning Over Time

Meaning is not static. Objects accumulate logs over time — events, descriptions, interpretations — that shift their semantic envelope.

The method handles this by:  
\- Registering the object once at creation  
\- Attaching logs that accumulate over time  
\- Computing definition vectors from logs up to a specified point  
\- Allowing time-based queries (e.g., "what did this mean in 1950?")

Time is a \*\*query filter\*\*, not a versioning axis.

\#\# 7\. Comparison to Embedding Models

| Feature | Embedding Models | This Method |  
|---------|------------------|-------------|  
| Interpretability | Low — dimensions have no meaning | High — axes are explicit |  
| Determinism | Stochastic | Deterministic |  
| Cultural nuance | Flattened | Preserved |  
| Time awareness | Static | Dynamic via logs |  
| Boundary control | Hidden in training | Explicit thresholds |  
| Cross-language | Mixed | Explicit with language tags |

\---

\#\# 8\. Conclusion

This method provides a structured, interpretable alternative to black-box similarity models. By combining:

\- \*\*Eidonomic context\*\* (hypernym/hyponym relationships)  
\- \*\*Explicit axes\*\* (relevant, significant dimensions)  
\- \*\*Weighted scoring\*\* (significance-based prioritization)  
\- \*\*Arbitrated thresholds\*\* (controlled boundaries)

The system produces similarity scores that are:

\- \*\*Explainable\*\* — each score traces to specific axes and weights  
\- \*\*Controllable\*\* — thresholds and weights are set by the designer  
\- \*\*Nuanced\*\* — captures cultural, temporal, and linguistic differences  
\- \*\*Grounded\*\* — anchored in the eidonomic tree

The ontonym is recognized as inherently fuzzy. This method does not eliminate the fuzz — it governs it.
