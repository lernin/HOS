Procedia Interactive OCR Recovery System

Turning OCR Failures into Gamified Learning Moments

Author: Ashley

Date: May 27, 2026

Status: Design Specification

\---

1\. Executive Summary

This document describes a novel feature for the Procedia writing correction system. When the OCR engine cannot confidently recognize a handwritten word, the system does not simply fail or guess. Instead, it engages the student interactively.

The system displays a corrected sentence with a placeholder for the unrecognized word. The student can tap the placeholder to see a cropped image of their original handwriting. They can then type the word, speak it, or indicate they don't know it. The system validates their input, awards gamification points, and uses the new data to improve future recognition and mastery tracking.

This feature turns OCR failures from a technical limitation into a pedagogical opportunity.

\---

2\. The Core Problem

Existing OCR systems have a binary outcome. Either they recognize the text, or they do not. When they fail, the user experience stops. The student sees an error or a blank space. No learning happens. No progress is made.

For children with messy handwriting, OCR failure is common. This creates frustration and breaks the learning flow.

Procedia solves this by making the student a participant in the recognition process.

\---

3\. The Core Insight

When OCR fails, the system does not need to guess. It can ask the student for help.

The student wrote the word. They know what they intended. By asking them, the system turns a failure into an active learning moment.

Additionally, students are motivated by gamification. Points, badges, and achievements incentivize them to help the AI rather than ignoring unrecognized words.

\---

4\. Technical Components

4.1 OCR Confidence Scoring

PP-OCRv5 provides a confidence score for every recognized word. Scores range from 0.0 to 1.0.

Confidence Range Meaning Action  
0.9 \- 1.0 Very confident Accept automatically  
0.7 \- 0.9 Moderately confident Accept, but flag for review  
0.5 \- 0.7 Low confidence Flag for student interaction  
0.0 \- 0.5 Very low confidence Require student interaction

The threshold can be adjusted. For messy student handwriting, a threshold of 0.7 is recommended.

4.2 Cropped Word Images

When a word has low confidence, the system saves its bounding box coordinates. It crops the original image to extract just that word. This cropped image is stored temporarily and displayed to the student when they tap the placeholder.

The cropped image is small. It takes minimal storage. It can be deleted after the student confirms the word or after a session ends.

4.3 Speech Recognition Integration

The system includes a microphone button. When pressed, the student can speak the word. Offline speech recognition handles English and Korean.

Two options for speech recognition:

Option Pros Cons  
Vosk (offline) Free, private, works without internet Slightly lower accuracy  
Whisper (local) High accuracy, offline capable Larger model size

For student devices, Vosk is recommended due to its small size and adequate accuracy.

4.4 Gamification Database

The system tracks student interactions with unrecognized words.

Field Description  
student\_id Unique student identifier  
word\_surface The word the student entered  
word\_atomonym The full atomonym (surface.lemma.pos.sense)  
interaction\_type typed, spoke, or dont\_know  
points\_awarded Number of points earned  
timestamp When the interaction occurred  
was\_correct Whether the student input matched the expected word

4.5 Mastery Integration

When a student successfully identifies a word, the system updates mastery for that word's atomonym. The student receives a positive evidence event. Stability increases.

When a student says "I don't know", the system flags the word as a vocabulary gap. The teacher can review these gaps. The system schedules spaced repetition for that word.

5\. User Experience Flow

Step 1: Student Submits Writing

The student takes a photo of their handwritten work. OCR processes the image.

Step 2: Low Confidence Detection

OCR completes with low confidence for one or more words. The system flags these words.

Step 3: Display Corrected Sentence

The system shows the corrected sentence. Unrecognized words appear as tappable placeholders. Example: "I went to the store and bought a \[???\]"

Step 4: Student Interaction

The student taps a placeholder. A popup appears showing:

· The cropped image of their original handwritten word  
· A text input field  
· A microphone button  
· An "I don't know" button

Step 5: Student Input

The student can:

· Type the word and submit  
· Speak the word (speech recognition fills the text field)  
· Tap "I don't know"

Step 6: Validation

If the student types or speaks a word, the system compares it to the expected word (if known) or accepts it as a new entry. Points are awarded.

If the student says "I don't know", the system notes the gap and schedules future review.

Step 7: Sentence Update

The placeholder is replaced with the confirmed word. The sentence becomes complete.

10\. Potential Concerns and Mitigations

Concern Mitigation  
Students abusing "I don't know" Teacher dashboard flags excessive use  
Privacy of voice recordings Delete audio after transcription, parent consent  
Offline speech accuracy Accept only high-confidence transcriptions  
Gamification distracting from learning Points are positive reinforcement, not required

11\. Conclusion

The Procedia Interactive OCR Recovery System transforms a technical limitation into a pedagogical advantage. When OCR fails, the system does not break. It engages the student in active learning.

The student helps the AI. The AI teaches the student. Gamification makes it fun.

This feature aligns with Procedia's core philosophy: learning is collaborative, not passive. Every interaction builds mastery.
