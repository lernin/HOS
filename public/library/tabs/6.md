### **Emergency event rules (invariants)**

  - **\*\*Emergency declarations apply only to schools, never to homes.\*\*\*\*  &#10;  &#10;\*\***
  - **\*\*Emergency-only data is readable iff:\*\*\*\*  &#10;  &#10;\*\***  
      - **\*\*an\*\* \*\*emergency\\\_events\*\* \*\*row exists\*\*\*\*  &#10;  &#10;\*\***
      - **\*\*status = active\*\*\*\*  &#10;  &#10;\*\***
      - **\*\*school\\\_id\*\* \*\*and\*\* \*\*subject\\\_person\\\_id\*\* \*\*match\*\*\*\*  &#10;  &#10;\*\***
  - **\*\*Emergency access persists until explicitly resolved or cancelled.\*\*\*\*  &#10;  &#10;\*\***
  - **\*\*Home access to emergency data is never mediated by this table.\*\*\*\*  &#10;  &#10;\*\***

### **Authority and resolution**

  - **\*\*Any school staff member with appropriate capability may declare an emergency.\*\*\*\*  &#10;  &#10;\*\***
  - **\*\*While active:\*\*\*\*  &#10;  &#10;\*\***  
      - **\*\*the declaring staff member may view emergency-only data\*\*\*\*  &#10;  &#10;\*\***
      - **\*\*other authorized school staff may view emergency-only data\*\*\*\*  &#10;  &#10;\*\***
  - **\*\*An emergency may be resolved or cancelled by:\*\*\*\*  &#10;  &#10;\*\***  
      - **\*\*the staff member who declared it, or\*\*\*\*  &#10;  &#10;\*\***
      - **\*\*the home primary person\*\*\*\*  &#10;  &#10;\*\***

**Resolution or cancellation:**

  - **\*\*requires explicit confirmation\*\*\*\*  &#10;  &#10;\*\***
  - **\*\*immediately seals emergency-only data again\*\*\*\*  &#10;  &#10;\*\***
  - **\*\*is logged with actor and timestamp\*\***

  - duration
  - start\_date

  - timezone (required / NOT NULL)

\# Rule:

\# For a given section\_id, schedules must not overlap in time.

\# Only one schedule may be active for a section on any given date.

  
  

schedule\_overrides

  - id (PK)
  - schedule\_id (FK → schedules.id)
  - override\_type (cancel | reschedule | substitute)
  - override\_data
  - date (required / NOT NULL)

  

\# Rule:

\# date identifies the exact calendar day the override applies to.

\# override\_data must fully describe the override payload.

  

days\_of\_week (int bitmask)

  

\# Bit mapping:

\# 1 = Monday

\# 2 = Tuesday

\# 4 = Wednesday

\# 8 = Thursday

\# 16 = Friday

\# 32 = Saturday

\# 64 = Sunday

  

\# Examples:

\# Mon/Wed/Fri → 1 + 4 + 16 = 21

\# Tue/Thu → 2 + 8 = 10

\# Sat only → 32

# **15. Learning Artifacts & Mastery**

Student outputs and the mastery signals derived from them.

Procedia tracks learning at two levels:

  - Concept mastery (atoms: words, grammar, traits)
  - Artifact mastery (chunks: sentences, paragraphs, speeches, model answers)  
      

Both are first-class.

## **artifacts** (Phase 0)

  - id (PK)
  - person\_id (FK → persons.id, NOT NULL) — learner / owner
  - text (TEXT, NULL) — written or transcribed content
  - corrected\_from\_id (FK → artifacts.id, NULL) — revision lineage
  - created\_at (TIMESTAMP, NOT NULL)

Represents one submission or stored learning unit.

An artifact may represent:

  - A writing submission
  - A sentence to memorize
  - A dialogue
  - A speech
  - A model paragraph
  - An audio recording (spoken response, shadowing, pronunciation sample)
  - A video submission (presentation, performance, explanation)
  - An image-based response (worksheet photo, drawing, diagram)
      
      - Artifacts are raw. They contain no evaluation logic.

## Media (Phase 0)

Generic stored file objects. May attach to a person and/or artifact.

  - id (PK)
  - person\_id (FK → persons.id, NULL) — uploader
  - artifact\_id (FK → artifacts.id, NULL) — optional attachment
  - kind (TEXT, NOT NULL) — image | audio | video
  - storage\_path (TEXT, NOT NULL, UNIQUE)
  - content\_type (TEXT, NOT NULL)
  - bytes (BIGINT, NOT NULL)
  - width (INT, NULL)
  - height (INT, NULL)
  - created\_at (TIMESTAMP, NOT NULL)
  - expires\_at (TIMESTAMP, NULL)  
      

Multiple media rows may attach to one artifact.

## concept\_judgment

Represents one evaluative event for a concept.

  - id (PK)
  - person\_id (FK → persons.id, NOT NULL)
  - concept\_id (FK → concepts.id, NOT NULL)
  - artifact\_id (FK → artifacts.id, NULL)
  - facet (ENUM/TEXT, NOT NULL) — meaning | spelling | pronunciation | usage | grammar | trait
  - lane (ENUM/TEXT, NOT NULL) — recognition | production
  - rung (ENUM/TEXT, NOT NULL) — introduction | reproduction | comprehension | recognition | production | application | transmission
  - is\_correct (BOOLEAN, NOT NULL)
  - strength (INT, NOT NULL DEFAULT 1 CHECK (strength BETWEEN 0 AND 5))
  - notes (TEXT, NULL)
  - created\_at (TIMESTAMP, NOT NULL)

Notes:

  - Each row is historical.
  - strength = 0 means minimal or weak signal.
  - strength = 5 means very strong signal.
  - This table never stores current state.  
      

## concept\_mastery (state)

Stores current mastery state for a concept per person.

  - person\_id (PK part, FK → persons.id, NOT NULL)
  - concept\_id (PK part, FK → concepts.id, NOT NULL)
  - facet (PK part, ENUM/TEXT, NOT NULL)
  - lane (PK part, ENUM/TEXT, NOT NULL) — recognition | production
  - rung (ENUM/TEXT, NOT NULL)
  - stability (INT, NOT NULL DEFAULT 0)
  - due\_at (TIMESTAMP, NULL)
  - last\_at (TIMESTAMP, NULL)
  - confidence (INT, NULL) — 0–3 UI roll-up
  - updated\_at (TIMESTAMP, NOT NULL)  
      

PRIMARY KEY (person\_id, concept\_id, facet, lane)

Notes:

  - Stores state (scheduling + roll-up), not history.
  - History lives in concept\_judgment.
  - Facet separates spelling / pronunciation / trait.
  - Lane separates recognition vs production.  
      

## artifact\_mastery (state — core)

Stores spaced repetition state for whole artifacts.

Used for:

  - Sentence memorization
  - Dialogue repetition
  - Speech rehearsal
  - Model paragraph retention
  - person\_id (PK part, FK → persons.id, NOT NULL)
  - artifact\_id (PK part, FK → artifacts.id, NOT NULL)
  - stability (INT, NOT NULL DEFAULT 0)
  - due\_at (TIMESTAMP, NULL)
  - last\_at (TIMESTAMP, NULL)
  - confidence (INT, NULL) — 0–3 UI roll-up
  - updated\_at (TIMESTAMP, NOT NULL)  
      

PRIMARY KEY (person\_id, artifact\_id)

Notes:

  - This schedules whole-language units.
  - Concept extraction may occur, but is not required.
  - Artifact mastery operates independently of concept mastery.  
      

Now your system clearly supports:

Atoms → concept mastery  
 Chunks → artifact mastery

## **21. Library Copies**

Physical copies (barcoded/stickered) for lending.

### library\_copies

  - id (PK)
  - product\_id (FK → products.id)
  - inventory\_location\_id (FK → inventory\_locations.id, nullable)
  - copy\_code *(barcode / sticker code, unique)*
  - condition *(new | good | worn | damaged, nullable)*
  - status *(available | checked\_out | lost | retired)*
  - created\_at
  - updated\_at  
      

each row = one physical book

  

Why this matters:

  - multiple copies of the same title
  - damaged vs good copies
  - lost books
  - clean audits  
      

  

### library\_loans

  - id (PK)
  - library\_copy\_id (FK → library\_copies.id)
  - borrower\_person\_id (FK → persons.id)
  - checked\_out\_at
  - due\_at (nullable)
  - returned\_at (nullable)
  - handled\_by\_person\_id (FK → persons.id, nullable)
  - notes (nullable)
  - created\_at

  

This gives you:

  - each row = one loan event
  - who has the book
  - when it’s due
  - overdue logic
  - history per student
  - “lost book” handling without deleting anything
