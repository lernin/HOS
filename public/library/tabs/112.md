# **Type Determination via Event-Role Distribution (ERD Framework)**

## **Executive Summary**

This paper introduces a method for determining whether an entity belongs to a type:

> **Classify based on how frequently an entity functions as that type across real-world events.**

This avoids misclassification caused by:

* capability-based reasoning  
* rare edge cases  
* incidental behavior

---

## **1\. The Core Problem**

Naive classification asks:

> “Can this thing do X?”

This fails because:

* many objects can perform multiple roles  
* rare capabilities distort classification

Example:

* Skis can be used for locomotion → but are not vehicles

---

## **2\. Core Principle**

> **Type is determined by dominant functional role across events**

NOT:

* what it *can* do  
* what it *sometimes* does

BUT:

* what it **reliably does across real-world usage**

---

## **3\. The ERD Method**

### **Step 1 — Define Target Type**

> Clearly define the type using a functional core

Example:

> Vehicle \= artifact whose primary function is locomotion

---

### **Step 2 — Event Sampling**

> Generate a broad set of real-world events involving the object

---

### **Step 3 — Role Evaluation**

For each event:

> **Does the object function as the target type in this event?**

(Binary: Yes / No)

---

### **Step 4 — Distribution Calculation**

> Measure the proportion of events where the answer is YES

---

### **Step 5 — Threshold Decision**

> **If usage ≥ threshold → classify as that type**

Suggested working threshold:

> **\~30%**

---

## **4\. Interpretation of Threshold**

* **\>70%** → strong type identity  
* **30–70%** → hybrid / dual-role  
* **\<30%** → not a type (minor role only)

---

## **5\. Examples**

### **Skis**

* Vehicle-role usage ≈ 12%  
  → **Not a vehicle**

---

### **Bicycle**

* Vehicle-role usage ≈ 80%  
  → **Vehicle**

---

### **Skateboard**

* Vehicle-role usage ≈ 30–50%  
  → **Borderline / weak vehicle**

---

### **Forklift**

* Vehicle-role usage low  
* Lifting dominates

→ **Not a vehicle**

---

## **6\. Separation of Concepts**

| Concept | Meaning |
| ----- | ----- |
| Type | What it *is* (based on dominant role) |
| Role | What it *does in an event* |
| Capability | What it *can do* |

> **Type emerges from role distribution, not capability**

---

## **7\. Integration with Axis Classification**

Once type is confirmed:

> Apply axis analysis (e.g., medium: land / water / air / space)

---

### **Example:**

Hovercraft:

* Passes Type Gate (vehicle)  
* Matches: land \+ water  
  → **Amphibious vehicle**

---

## **8\. Key Insight**

> **Identity is statistical across events, not absolute per instance**

---

## **9\. One-Line Algorithm**

> **Event → Role → Distribution → Threshold → Type → Axis**

---

## **10\. Implications**

* Eliminates edge-case pollution  
* Enables hybrid detection  
* Improves ontology precision  
* Aligns with real-world usage patterns
